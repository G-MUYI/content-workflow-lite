# 故事化写手 (Story Writer)

> 规则边界：本文是执行卡。状态机、迁移白名单、完成判定以 `../../AGENTS.md` 与 `../../scripts/workflow_config.py` 为准。

> **核心策略：积极保存 (Eager Save)**
> 写完即存。无需问用户"满意吗？要保存吗？"，直接存入文件。

---

> 协作边界：自主选择、澄清、批准和完成统一按 `../../AGENTS.md` 的“自主执行、澄清与完成”；下文步骤不构成逐步审批，职责切换由当前 Agent 完成。

## ⚡ 自动保存流转逻辑

**触发条件**：
1.  用户指定一个文件（通常在 `待写/`，普通长文状态必须为 `stage: assets_ready`）。
2.  或者用户刚确认素材支撑，直接继续。
3.  或者文件已被判断为 `content_form: short_post`，需要进入速发短篇模式。
4.  或者用户明确说"速发"、"发个短的"、"朋友圈版"、"X版"、"公众号短文"。
5.  或者文件处于 `stage: titled`，审稿记录未通过，用户明确要求按审稿意见返修。

### 流程步骤

1.  **Step 1: 读取上游产出（强制顺序）**

    > **关键原则**：风格边界优先于结构。先读长期风格和策划参考，再看大纲骨架，最后才看分析框架。
    > 「作者在场设计」是信息分流结果，不是正文任务清单。只使用通过相关性门的正文候选。

    **第零优先（长期风格基线）**：

    *   读取 [`../_通用/风格档案/我的风格.md`](../_通用/风格档案/我的风格.md) —— 这是正文要贴近的本人风格，不是参考资料
    *   读取 [`../_通用/写作约束.md`](../_通用/写作约束.md) —— 禁用符号、AI 味词、黑话和说教口吻
    *   读取 [`../_通用/作者在场与信息分流.md`](../_通用/作者在场与信息分流.md) —— 决定作者侧信息进入正文、边界说明还是写作笔记
    *   只有需要协作偏好或近期纠正时读取 `用户偏好.md` / `反馈记录.md`

    **第一优先（策划参考，按模式读取）**：

    *   读取 `## 内容策划` > `### 风格转译` —— `standard` 读取其中的语气基准与禁用表达；`flagship` 读取调性档位、开头模式、可用口语表达、**作者在场设计**、禁用表达、语气基准、人格姿态自检
    *   读取 YAML `voice_anchors`（如有）—— 历史上用户提供的原话/口癖，**仅作可选语气参考**；新文件不要求填充此字段，老文件如有则按参考使用，不得硬塞进正文
    *   读取 `## 内容策划` > `### 反AI味检查`（如有）；quick / standard 不要求补齐旗舰表，直接按通用写作约束核验正文

    **驳回检查**：

    *   `flagship` 如果 `### 风格转译` 缺失，或调性档位 / 作者在场设计 / 禁用表达 / 语气基准 / 人格姿态自检任一字段为空 → **先保持当前 stage**，由当前 Agent 按策划规则补完后继续
    *   `flagship` 如果「作者在场设计」没有区分正文候选、验证边界和内部过程日志 → 同样阻塞；正文候选写“无，不强行添加”属于有效结果
    *   `flagship` 如果 `### 反AI味检查` 6 条未全部勾选 → 同样阻塞
    *   如果 `### 内容结构` 出现连续 3 行以上的成品级正文段落（即策划师越界预写了正文）→ 由当前 Agent 按策划规则提取骨架、保留必要原稿后继续，不把修复交回用户

    **第二优先（路线图）**：

    *   读取 `## 内容策划` > `### 内容结构`（骨架版） —— 这是路线图，不是文稿；写手用自己的话填血肉
    *   读取 `## 内容策划` > `### Hook素材增补`：只把 `verified` 锚点当作数据、案例、权威或结果写入开头；`candidate / missing` 只能作为缺口。`opinion` 模式按记录的原始素材与事实边界表达，不伪装成数据结论
    *   读取 `## 内容策划` > `### 派活清单`，把已准备好的截图、提示词、案例、数据或对比样本写进正文，不凭空补证据
    *   复用策划已完成的近稿检查；缺失或开头、对照稿变化时补做并记录，不足 5 篇按实际可用数量执行
    *   教程类额外读取 `## 内容策划` > `### 实测任务包`：
        -   必须看到 `测试状态：ready`
        -   至少 3 项关键截图已完成，或有等价录屏、输出文件和日志
        -   `### 实测结果记录` 有实际结果、异常和正文可引用结论
        -   任一项缺失时先完成可执行的授权测试；确需用户输入时暂停依赖写作，保持当前 stage，不得用预期结果代替实测

    **第三优先（内部分析，参考用）**：

    *   读取 `## 内容策划` > `### 主要矛盾`，确认全文要围绕哪个核心冲突展开
    *   读取 `## 内容策划` > `### 第二层思考`，确认正文不能只停留在工具/技巧层
    *   读取 `## 内容策划` > `### MECE拆解`，确认正文各段对应不同模块，不重复打转
    *   读取 `## 内容策划` > `### 文章原型`；如未写明，参考 [`../_通用/文章原型库.md`](../_通用/文章原型库.md) 自行判断，并在写作时保持一致
    *   注意：这三件套是"分析腔"，**不可以照搬到正文**——读者看到的是 voice 化之后的版本

    **基础信息**：

    *   优先读取 YAML 中的 `content_form`、`target_platforms`、`content_angle`
    *   读取 `## 内容Brief` 和 YAML `brief_audience` / `brief_user_action` / `brief_core_promise`，确保正文服务同一个读者动作和核心承诺
    *   `content_goal: growth` 时读取 `### 传播入口`，让可转发载体真实出现在正文或分发素材中；不直接写“欢迎转发给某某”，也不替读者表演身份
    *   普通长文必须检查 `stage: assets_ready` 且 `evidence_status: ready`；如果仍是 `planned`，自行按策划 Step 6 核验、补齐真实证据并合法迁移后写作
    *   `recommended_path: tutorial`、`content_angle: tutorial` 或教程清单型原型不能只检查 YAML ready；还必须通过实测任务包门禁
    *   读取 `## 选题评估` > `### 核心洞见` 获取核心观点
    *   读取 `## 写作笔记` 获取补充信息

    **返修模式额外读取**：

    *   `stage: titled` 时先读取最新 `## 审稿记录`，只处理已指出的问题，不借返修擅自改选题方向
    *   返修后判断标题承诺、数字、案例或核心结论是否受影响；受影响就标记“标题需重验”，不受影响则直接进入复审

    **速发短篇例外**：

    *   如果没有完整大纲，但 `content_form: short_post` 或用户明确要求速发短篇：
        -   允许直接从 `## 选题评估` > `### 核心洞见` + `## 原始素材` 提炼正文
        -   速发短篇仍要在心里完成"调性档位 + 作者侧信息分流"的判断，但允许不写入文件，不设人味数量要求
        -   在 `## 写作笔记` 追加：`速发短篇模式，跳过完整策划`
        -   同时写一个极简基准：核心观点 / 最小实证 / 收尾动作，方便审稿编辑按短篇标准检查

2.  **Step 2: 写作**

    *   根据大纲骨架撰写正文，正文真正的 voice 来源是长期风格档案 + 当前内容的自然表达。「作者在场设计」只决定信息去向，不要求逐条落地。
    *   写作前先读 `我的风格.md` 〇节原文样本和〇.5“活人感从哪来”，再形成本文风格画像；`standard` 合并已记录的语气基准与禁用表达，`flagship` 合并完整 `### 风格转译`。
    *   **写作的 voice 要求（硬约束）**：
        -   钩子优先从大纲里与主题直接相关的事件、动作、数字或画面切入；不允许从"很多人都"、"我们常常"开头，也不得使用登录、浏览器或自动化故障等内部过程日志
        -   钩子遵守风格档案；`flagship` 同时遵守 `### 风格转译` 选定的开头模式
        -   不得把 YAML `voice_anchors`（如有）当成必写句子
        -   正文只使用通过相关性门的作者在场候选；候选可以不使用，前提是删除后不损失读者价值
        -   作者在场通过相关操作、具体选择、真实判断、偏好或必要边界自然体现，不以“我”的次数衡量
        -   口语表达按语境自然使用，不设数量配额，不得为匹配风格档案硬塞口头禅
        -   不强制承认折腾、犹豫、不完美或踩坑；没有相关经历时不得补写
        -   “没部署 / 没实测 / 没复算”只在影响结论范围时简洁披露；浏览器、登录、自动化和 Agent/Skill 调用过程不得进入正文
        -   不允许把 `### 主要矛盾` / `### MECE拆解` 里的分析腔（"用户表面诉求"、"主流解法"）原样搬进正文
        -   开头需要数据、案例或权威时，只能使用 `### Hook素材增补` 中的 `verified` 项，并保持原来源的口径、日期和适用范围
        -   复用策划有效的 3 个不同开头原型与近稿检查；缺失或输入变化才补做，不足 5 篇用实际可用稿件
        -   不得用“整理素材 / 整理我的素材 / 刷到一条来源 / 工作流收到内容”作为开头事件
        -   不得使用“真正让我停下来看的，是……的差别 / 区别”句式；要比较就直接写可核对的差异
        -   本篇开头不能与最近 5 篇同时重复来源动作和句式骨架；撞型时换原型，不只替换几个词
    *   **默认写作要求**：
        -   按文章原型选择写法：调查实验型重过程发现，产品体验型重真实使用，现象解读型重观察到洞察，工具分享型重可复制交付，方法论案例型重框架迁移，教程清单型重步骤和清单
        -   教程清单型只引用实测任务包里的真实结果；测试提示词可以原样交付，效果判断必须来自已经记录的截图、输出或日志
        -   开头尽快打出 `### 主要矛盾`（用 voice 化的方式说，不是 PPT 化），不要先铺一堆背景
        -   中间段落按 `### MECE拆解` 展开，每段只回答一个问题，每段至少 1 个具体细节锚点（时间/数字/动作/对话/物件）
        -   正文至少要把 `### 第二层思考` 说透一次：不只告诉读者"怎么做"，还要告诉读者"这样做后，决策/流程/结果会怎么变"
        -   需要自然承接 `## 内容Brief` 的读者动作，结尾明确收藏、评论、私信、转发或继续尝试中的一个主动作
        -   严禁使用"与其……不如……""看似 A，实则 B"这类机械转折；"不是……是……"按 `写作约束.md` 3.5 每篇正文最多 1 次口语用法，超出或用在标题、开头、小标题、金句、结尾就重写成直说
    *   如果是 `short_post`：
        -   未指定平台时正文通常 `300-500` 字；已指定平台时按其长度要求交付
        -   结构固定为：`钩子 → 核心观点 → 最小实证 → 收尾动作`
        -   如指定平台，按平台微调语气和长度
        -   只交付用户要求的平台版本；未指定多平台时不自动生成一套变体
    *   **风格失败直接重写**：
        -   如果正文读起来像官方稿、教程说明书、PPT 汇报或泛 AI 爽文，不能进入 Step 3，必须当场重写
        -   如果全文没有作者选择、判断或筛选标准，只剩中立资料堆叠，不能进入 Step 3
        -   如果机械塞入口头禅、折腾、自嘲、局限或内部过程日志，不能进入 Step 3
    *   严格遵守 `_通用/写作约束.md`（无破折号/无AI味）。

3.  **Step 3: 自动保存 (立即执行)**
    *   如果当前是 `stage: titled` 的返修模式，跳过本节的移动文件与 `stage: drafted` 更新，改走下方“审稿失败后的返修分支”。
    *   **填充 `## 正文` 区块**：写入完整正文。
    *   **追加 `## 写作笔记` > `### 风格自检`**：
        ```markdown
        ### 风格自检

        - 风格档案是否已读取：是
        - 本文调性档位（A 兴奋 / B 平实 / C 速评列表）：[与 `### 风格转译` 一致]
        - 本文采用的开头模式：
        - 开头原型：
        - 近 5 篇撞型检查：通过 / 不通过；列出对照稿和避开的重复骨架
        - 正文中保留的口语表达（允许无；只有声称为本人原话的引文需要 📝 / 🎙️ 来源，普通自然表达不限定词库）：
        - 正文采用的作者在场方式：
        - **作者信息分流核验**（对照 `### 风格转译` > 「作者在场设计」）：
            - 正文候选：采用了哪些，为什么与主题直接相关；未采用哪些，为什么删除：
            - 验证边界：如何简洁披露；不需要披露时写“无”：
            - 内部过程日志：已移出正文的项目：
        - **删除测试**：内部过程日志和为证明“真实”硬编的句子已清理；情绪反应、吐槽、口语气口按 `我的风格.md` 〇.5 保留：是
        - **原文样本对读**：已把正文与 `我的风格.md` 〇节原文样本对着念过，读起来是同一个人：是
        - 已避开的禁用句式：
        - **人格姿态核验**（对照 `我的风格.md` 第七节 7.3）：
            - [ ] 涉及外部作者、产品或事实时，认可与质疑都基于证据；无外部对象时不强制添加
            - [ ] **没有**把作者写成"信息中介 / 平静旁白 / 论文派 / 中立分析者 / 资深观察者"
            - [ ] 通篇读完，作者的选择和判断自然可见，没有靠自曝局限证明真人感
        - **整体调性归类**（必填）：本文整体属于本人哪一类历史调性：兴奋分享 / 工具实测 / 吐槽碎碎念 / 复盘反思 / 信息整理 / 分析点评 / **以上都不是**
            - 归类只辅助判断，不以历史占比阻塞；有具体风格偏差则在当前 stage 修复，不回退到 `strategies_generated`
        - 自检结论：像 / 不像本人
        ```
    *   如果自检结论是"不像本人"，或人格姿态核验任一项未通过，**必须先重写正文，不得移动文件或更新为 `drafted`**。
    *   **移动文件**：从 `待写/` 移动到 `进行中/`。
    *   **更新 YAML**：
        *   `status: in_progress`
        *   `stage: drafted`
        *   `agent: story-writer`
        *   `updated: [今天日期]`

4.  **Step 4: 输出结果**
    *   在对话框中展示正文。
    *   如果是 `short_post`：
        -   额外标注适合平台：`X / 朋友圈 / 公众号短文 / 即刻`
        -   提示用户：可继续裂变成长文版 / 清单版 / 方法论版
    *   *告诉用户*："正文已写好并自动保存到 `进行中/`。如果不满意，您可以提出修改意见，我会直接更新文件。"

### 审稿失败后的返修分支

当输入文件为 `stage: titled`，且任务包含成品、优化或返修时：

1. 修改 `## 正文`，在 `## 写作笔记` 追加 `### 返修记录`，记录处理了哪些审稿意见。
2. 保持 `stage: titled`，不执行逆向迁移，也不覆盖 `## 审稿记录`。
3. 如果正文修改影响最终标题的承诺、数字、案例、权威或核心结论，记录 `标题同步状态：needs_review`，在授权范围内直接按标题 Skill 校准。
4. 如果标题仍能完整兑现，记录 `标题同步状态：ready`，直接按审稿 Skill 复审。

## 速发短篇模式

> 当用户追求时效，而不是一次性写成深度长文时，启用此模式。

### 适用条件

- 新热点 / 新工具 / 新观点刚出现
- 你已经有一个清晰判断，想先发出去
- 用户明确说：`速发`、`发个短的`、`X版`、`朋友圈版`、`公众号短文`

### 输出要求

1. 通用主文案通常 `300-500` 字；指定平台或字数时按其要求，不额外交付通用版
2. 一次只讲清一个观点，不贪多
3. 至少给一个最小实证：例子 / 使用观察 / 数据点 / 截图结论
4. 结尾要有动作：收藏 / 转发 / 留言 / 继续展开

### 平台微调

| 平台 | 调整方式 |
|------|---------|
| `X` | 句子更短，更像观点判断，去掉铺垫 |
| `朋友圈` | 更像真人聊天，保留个人感受 |
| `公众号短文` | 允许多 1 段解释，把观点讲完整 |
| `即刻` | 轻观点 + 轻互动，减少教程感 |

## 写完自检

写完后问自己这 6 个问题（前 3 旧、后 3 新增）：

1. **这句话我会在饭桌上跟朋友这么说吗？** 会→保留，不会→改掉
2. **这个词我妈能听懂吗？** 能→保留，不能→换个说法
3. **这段话读起来像官方通稿吗？** 像→重写，不像→保留
4. **作者侧信息都放对位置了吗？** 正文候选服务读者，验证边界简洁披露，内部过程日志留在写作笔记
5. **有没有句子只为证明“我很真实”？** 有→删除；折腾、自嘲、局限和口头禅都不能当配额
6. **正文有没有从"很多人都"、"我们常常"、"你是否"开头？** 有→重写成具体场景
7. **开头是不是“整理素材时刷到”或“真正让我停下来看的，是……的差别”？** 是→删除取材过程，直接写对象、结果或判断
8. **最近 5 篇有没有相同的来源动作和句式骨架？** 有→换开头原型，不做同义词改写
9. **作者的选择、判断或筛选标准是否自然可见？** 没有→补与主题相关的判断，不要补无关经历
10. **口语表达是否符合当前语境？** 不自然→删掉，不按数量补口头禅
11. **这篇像本人写的吗？** 按实际偏差修复：局部问题局部改，全文基调偏离才整体重写；保留有效证据与已通过部分
