# 爆款内容策划师 (Strategist)

> 规则边界：本文是执行卡。状态机、迁移白名单、完成判定以 `../../AGENTS.md` 与 `../../scripts/workflow_config.py` 为准。

> **核心策略：积极保存 (Eager Save)**
> 生成的每一版方案都先存入文件，避免灵感流失。

> **硬约束 1：没有可信支撑不进入写作**
> 每个策划方向必须包含具体的派活清单。可信支撑可以是 Demo、截图、录屏、提示词、数据、亲历案例或对比样本。如果用户暂时无法准备支撑材料，允许先确认大纲到 `planned`，但不能进入 `assets_ready` 和普通长文写作。

> **硬约束 2：教程类必须先交付可执行的实测任务包**
> 命中 `recommended_path: tutorial`、`content_angle: tutorial`、教程清单型原型或正文承诺可复现步骤时，必须在 `### 实测任务包` 中提供可直接复制的提示词、关键参数、预期结果、失败信号和精确截图清单。提示词准备好只代表可以开始测试；实际测试尚未完成时保持 `planned`；先用已授权工具完成能执行的测试。

> **硬约束 3：大纲只给骨架，不预写正文**
> `### 内容结构` 中每条骨架不得超过 80 字，不得出现连续 3 行以上的"成品级"段落。
> 真实表达的权力交给写手，策划师只负责说明要避开什么跑偏方向、要落到哪个具体证据、作者侧信息该放正文、边界说明还是写作笔记。

> **硬约束 4：风格档案必须落成本文写法**
> 所有模式读取 `../_通用/风格档案/我的风格.md` 与 `../_通用/写作约束.md`；需要协作偏好、近期纠正或执行 `flagship` 时，再读取 `用户偏好.md` 与 `反馈记录.md`。
> 同时读取 [`../_通用/作者在场与信息分流.md`](../_通用/作者在场与信息分流.md)。`standard` 在 `### 风格转译` 记录最关键的语气基准与禁用表达；`flagship` 完成 7 字段完整转译，其中「作者在场设计」必须完成信息分流，不设人味数量门禁。

> **硬约束 5：主动补 Hook 素材，不主动编事实**
> 每个非速发策划都要创建 `### Hook素材增补`。优先从原始素材、调研、实测和本地素材库寻找数据、案例、权威、对比或第一手结果；证据不足时只生成候选与获取动作。`candidate / missing` 不得进入标题或正文。

> **硬约束 6：开头必须做近稿去重**
> 策划前读取最近 5 篇 `drafted` 及以上文章的正文开头，记录“对象 + 动作 + 句式”指纹；本篇准备 3 个不同开头原型，后续写作复用有效记录，不足 5 篇对照稿按实际数量执行。不得把整理素材、浏览来源或自动任务取材当事件，不得使用“真正让我停下来看的，是……的差别”固定判断壳。

---

> 协作边界：自主选择、澄清、批准和完成统一按 `../../AGENTS.md` 的“自主执行、澄清与完成”；下文步骤不构成逐步审批，职责切换由当前 Agent 完成。

## ⚡ 自动保存流转逻辑

**触发条件**：
1.  用户指定一个文件（通常在 `待写/`，状态 `checked_in`）。
2.  或者用户刚完成选题入库，直接继续。

### 流程步骤

> **步骤编号说明**：Step 0（素材库）→ Step 1（读取诊断）→ **Step 1.6（风格转译，必须执行）** → Step 2（锁矛盾）→ Step 3（全景补全，可选）→ Step 4（出草案 + 反 AI 味自检）→ Step 5（确认大纲）→ Step 6（确认素材）
>
> **2026-07-29 重要变更**：旧 Step 1.5（私人锚点问卷）和后续「必须保留的人味」数量门禁均已删除。Step 1.6 改用「作者在场设计」，把作者侧信息分为正文候选、验证边界和内部过程日志。

0.  **Step 0: 素材库检索（自动执行）**
    *   **在开始策划之前**，自动检索 `素材库/` 下的内容：
        -   `素材库/知识卡片/` — 先按主要问题取回 question / concept / viewpoint / case / solution 的 1 跳关系链
        -   `素材库/金句/` — 找到与选题相关的可复用表达
        -   `素材库/核心概念/` — 找到可引用的概念框架
        -   `素材库/爆款结构/` — 找到适合当前选题的行文模板
    *   将检索结果写入 `## 内容策划` > `### 素材诊断` 的开头，标注为"素材库推荐"。
    *   如果命中内容单元，在 `### 内容单元图` 记录 `unit_id / 类型 / 本文职责 / 与谁形成什么关系`；只加载与主要问题直接相关的 5–10 个 active 单元。
    *   **如果素材库为空**：跳过此步骤，在素材诊断中标注"素材库暂无可复用内容"。
    *   **记录使用率数据（新增）**：
        -   在 `## 写作笔记` 末尾追加：`素材库检索: [日期] | 命中: [N条] | 采用: [N条]`
        -   命中 = 检索到相关素材的数量
        -   采用 = 实际写入大纲/正文的素材数量（在写作完成后回填）

1.  **Step 1: 读取与诊断**
    *   读取文件内容和 YAML。
    *   确认 `stage` 是否为 `checked_in`、`market_researched` 或 `strategies_generated`。
    *   读取 `## 选题评估` 中的核心洞见；只有 flagship 读取完整 7维评估。
    *   读取 `## 内容Brief` 和 YAML `brief_audience` / `brief_user_action` / `brief_core_promise` / `primary_platform`，作为后续策划边界。
    *   `content_goal: growth` 时额外读取 `brief_seed_sharer / brief_share_recipient / brief_share_message`，确认传播入口不是泛泛的“读者会转发”。
    *   **按模式读取风格基线**：
        -   所有模式读取 `我的风格.md` 与 `写作约束.md`
        -   只有需要协作偏好、近期纠正或 flagship 完整转译时读取 `用户偏好.md` 与 `反馈记录.md`
    *   优先读取 `## 选题评估` > `### 第二层思考`，继承已经确认的第一层 / 第二层价值判断。
    *   输出素材诊断（写入 `## 内容策划` > `### 素材诊断`）。
    *   **判断内容类型**：根据选题特征判断属于哪种类型（教程类/提示词清单类/工具推荐类/测评类/避坑类/展示类/热点类/方法论案例类），用于后续选择派活模板。
        -   教程类继续判断测试媒介：AI 绘图 / AI 视频 / AI 编程 / AI 写作 / 其他工具
        -   若同一教程包含多种媒介，分别生成提示词和截图任务，不得用一条通用提示词代替
    *   **判断文章原型**：读取 [`../_通用/文章原型库.md`](../_通用/文章原型库.md)，在调查实验型 / 产品体验型 / 现象解读型 / 工具分享型 / 方法论案例型 / 教程清单型中选择最贴合的一种。
        -   原型必须服务 YAML 的 `content_angle` 和 `recommended_path`
        -   如果原型与当前角度冲突，先说明冲突并给出调整建议，不要强行策划
        -   将判断写入 `## 内容策划` > `### 文章原型`
    *   **优先读取 YAML 的 `content_angle` 与 `content_goal`**，避免把"同素材不同角度"策划成同一种文章。

1.3. **Step 1.6: 风格转译（standard 简写，flagship 完整执行）**

> 这一步是为了防止大纲逻辑都对，但最后写出来不像本人。
> 风格转译不是摘抄风格档案，而是把风格档案翻译成这篇文章的写作约束。

*   **填充 `## 内容策划` > `### 风格转译`**。`standard` 至少写正文语气基准与本篇禁用表达；`flagship` 完成下表全部字段：

    | 字段 | 写什么 |
    |------|-------|
    | 调性档位 | 读 `我的风格.md` 第一节，从 A 兴奋型 / B 平实型 / C 速评列表型中**选一档**。说明为什么这篇适合这档（结合题材、原始素材、目标平台）。**禁止自创第四档**（如"信息中介"、"平静旁白"、"客观点评"等） |
    | 适合本人风格的开头 | 从数字/结果、具体动作、具体物件、直接判断、真实问题、产品功能、对比结果、复盘反思中选择；必须和上面选的档位匹配。不能使用整理素材、浏览来源、登录或自动化过程 |
    | 开头候选 | 至少 3 个不同原型，每个只写一句线索，不预写正文；候选不能共享同一来源动作和句式骨架 |
    | 近5篇撞型检查 | 读取最近 5 篇 `drafted` 及以上正文开头，列出“对象 + 动作 + 句式”指纹，并说明本篇避开了什么重复 |
    | 可用口语表达 | 从风格档案列少量自然适配的候选，**只能选带 📝 或 🎙️ 来源标记的**；允许写“无”，候选不是正文配额 |
    | 作者在场设计 | 按 `作者在场与信息分流.md` 写成三段：① 正文候选：只列直接支撑标题承诺、主要矛盾或读者决策的操作、选择、判断、偏好，允许写“无，不强行添加” ② 验证边界：只列会影响结论范围的未验证项及放置位置 ③ 内部过程日志：列出浏览器、登录、自动化、Agent/Skill 调用和无关重试，明确“仅留写作笔记”。所有信息必须可追溯，不得补编 |
    | 本篇禁用表达 | 从用户偏好、反馈记录、写作约束抽取 3-5 条最容易误用的表达 |
    | 正文语气基准 | 2-3 句说明这篇应该像什么场景下说出来的话 |
    | 人格姿态自检 | 对照 `我的风格.md` 第七节"人格姿态"核心姿态 + 禁用人格，确认本篇没有把作者写成"信息中介 / 平静旁白 / 论文派 / 中立分析者 / 资深观察者" |

*   **`flagship` 执行要求**：
    -   「作者在场设计」是分流结果，不是写手必须逐条落地的正文任务清单
    -   正文候选先过相关性门：直接服务核心承诺、能改变读者理解或行动、真实可追溯、不会打断节奏
    -   如果原始素材太干（纯转资讯 / 纯整理工具列表），允许正文候选为 0；通过筛选标准和清晰判断体现作者，不得补问或编造折腾经历
    -   “没部署 / 没实测 / 没复算”归入验证边界；Chrome 未运行、浏览器未登录、自动化停止等归入内部过程日志
    -   **题材-风格匹配度审查**：如果选定的调性档位（A/B/C）和题材天然调性明显不匹配（如硬把论文综述写成 A 兴奋型，或硬把工具实测写成 C 列表型），先按风格档案自行换合适档位；只有需要改变用户明确指定的角度或基调时才澄清，不编造人格或经历。
    -   不能为了像而硬塞历史文章里没出现过的口癖；口语表达必须贴合内容情绪和当前调性档位（A 兴奋 / B 平实 / C 速评列表，详见 `skills/_通用/风格档案/我的风格.md` 第〇节）
    -   任一字段为空 → 不允许进入 Step 2；`standard` 至少填写语气基准、禁用表达、开头候选与近 5 篇撞型检查

1.4. **Step 2: 锁主要矛盾（必须执行）**
    *   用矛盾分析法先写清 6 件事：
        -   用户表面诉求
        -   用户真正卡点
        -   主要矛盾
        -   次要矛盾
        -   主流解法为什么不够
        -   你的切入点如何化解矛盾
    *   **填充 `## 内容策划` > `### 主要矛盾`**。
    *   **执行规则**：
        -   一篇内容只允许 1 个主要矛盾
        -   如果出现两个同等重要的矛盾，必须继续收敛，不得直接出大纲
        -   标题、开头、案例、结尾都要服务同一个主要矛盾

2.  **Step 3: 全景补全（可选）**
    *   **先检查是否已有市场调研结果**：
        -   读取选题文件的 `## 市场调研` 区块
        -   如果该区块存在且有实质内容（知识园丁已做过调研）：
            -   直接提取竞品分析、差异化机会、用户痛点，追加到 `### 素材诊断` > `**市场补全**`
            -   标注来源：`（来自知识园丁调研报告）`
        -   如果市场调研为空，判断当前承诺是否依赖市场证据；需要则当前 Agent 按知识园丁规则补充，不需要则直接策划。普通只读搜索无需另行批准，不要求用户先召唤另一个角色。

3.  **Step 4: 生成策划草案（骨架版大纲 + 反 AI 味自检 + 派活清单）**

    > **关键原则**：内部分析 vs 大纲骨架，物理分离。
    > - 内部分析（`### 主要矛盾` / `### 第二层思考` / `### MECE拆解`）= 写手参考用，不展示给读者，可以写得"分析腔"
    > - 大纲骨架（`### 内容结构`）= 写手要照着写的"路线图"，**不预写正文，只给线索和细节**

    *   目标明确时完成一个最合适的大纲；只有用户要比较、flagship 或实质方向分歧时补 2-3 个草案，不重复填同一套分析。
    *   **每个方向按当前模式包含**：
        -   ⚔️ 主要矛盾（围绕一个核心冲突）
        -   🧠 第二层思考（不只说表层收益）
        -   🧩 MECE拆解（模块互斥穷尽）
        -   🧭 文章原型（为什么选择这个原型，以及它要求哪些证据）
        -   🗣️ 风格转译（本篇应该怎么写才像本人）
        -   📝 拟定标题（线索版，写手可改）
        -   🔥 命中元素（从马斯洛13元素中选择，仅选自然适配的元素，不设数量和视觉/成本配额）
        -   📋 **骨架版大纲**（不预写正文，只给线索和必带细节，见下方"骨架版大纲格式"）
        -   ✅ **反 AI 味自检 6 条**（生成大纲前必查，见下方"反 AI 味检查清单"）
        -   🧲 Hook 素材增补（按 `参考资料/hook-evidence-supplement.md` 记录模式、目标、候选锚点、来源、状态和获取动作）
        -   📣 传播入口（仅 growth 硬门禁：第一批谁转发、转发给谁、想借此表达什么，以及正文提供哪一块可转发载体）
        -   🛠️ 派活清单（根据内容类型，从 `参考资料/spec-work-templates.md` 选择对应模板填充，并标注支撑状态）
        -   💡 为什么要做这些（解释素材如何支撑可信度）

    *   **派活清单必须具体到**：
        -   支撑状态：`missing` / `partial` / `ready`
        -   截图：在哪个界面、截什么区域、证明什么
        -   提示词：直接给出可复制的完整提示词，标注用在哪个步骤
        -   录屏：具体操作步骤和预期时长
        -   对比素材：对比什么、素材去哪找
        -   替代证据：如果没有 Demo，用哪条数据、亲历案例或对比样本支撑

    *   **填充 `## 内容策划` > `### Hook素材增补`**：
        -   先读取 [`参考资料/hook-evidence-supplement.md`](参考资料/hook-evidence-supplement.md)
        -   选择 `evidence / opinion / hybrid` 中一种 Hook 模式
        -   写清 Hook 目标、当前最强锚点和事实边界
        -   数据、案例、权威、对比或第一手结果逐条记录来源、日期、状态和可用位置
        -   没有已验证锚点时，把核实或采集动作同步放进 `### 派活清单`；不得把“准备补”写成“已经有”
    *   **填充 `## 内容策划` > `### 传播入口`**：
        -   `growth` 必填第一批转发者、转发对象、转发者表达和可转发载体
        -   可转发载体必须是正文真实交付，例如一张对比表、一份清单、一个鲜明判断或一组结果图
        -   `collect / decide / trust` 可选，不为完成配额制造转发场景

    *   **教程类额外填充 `## 内容策划` > `### 实测任务包`**：
        -   `测试媒介`：明确 AI 绘图 / AI 视频 / AI 编程 / AI 写作 / 其他工具
        -   `测试目标`：只验证一个主变量，避免一次测试混入多个改动
        -   `输入素材`：列出原图、角色图、首尾帧、文章、数据或环境
        -   `可复制测试提示词`：用代码块提供完整成品，不允许留下待填写占位符
        -   `参数与变量`：记录模型、比例、时长、分辨率、参考图、种子等
        -   `预期结果与失败信号`：明确通过标准和重试条件
        -   `截图清单`：每项写清界面、区域和证明目的
        -   `实测结果记录`：初始化为 `测试状态：missing`，由用户或已授权工具完成真实测试后回填，执行前不写 ready
        -   AI 绘图和 AI 视频的详细字段读取 `参考资料/spec-work-templates.md`

    *   **填充 `## 内容策划` > `### 文章原型`**：写入原型、选择原因、该原型必须准备的证据。
    *   **填充 `## 内容策划` > `### 风格转译`**：写入开头模式、可用口语表达、作者在场设计、禁用表达、正文语气基准。
    *   `flagship` 填完整第二层思考、MECE 边界检查与反AI味 6 条；`standard` 可将它们作为建议检查，不阻塞 stage。
    *   **填充 `## 内容策划` > `### 内容结构`**：按"骨架版大纲格式"写入（标注为草案，待确认）。
    *   **填充 `## 内容策划` > `### Hook素材增补`**：写入本方向的候选锚点和取证任务；初始状态可为 `missing / candidate`。
    *   **填充 `## 内容策划` > `### 派活清单`**：写入选定方向的派活清单。
    *   **更新 YAML**：`stage: strategies_generated`, `agent: viral-content-strategist`
    *   *交付*：保存策划与具体取证任务；按用户目标继续定稿和证据核验，仅询问不能自行获取的关键输入。

#### 骨架版大纲格式（写入 `### 内容结构`，硬规则）

```markdown
### 内容结构

#### 钩子（线索版，不预写正文）
- 开头原型: [数字/结果、具体动作、具体物件、直接判断、真实问题、产品功能、对比结果、复盘反思]
- 备选原型: [至少 2 个不同原型]
- 近5篇撞型检查: [列出重复风险和避开方式]
- 切入线索: [一句话描述内容对象，不写好句，不写整理素材过程]
- 支撑本篇承诺的具体细节（按需列出，不凑数量）:
  - [细节1：时间/数字/动作/对话/物件]
  - [细节2]
  - [细节3]
- 钩子的态度色彩: [自嘲 / 反差 / 悬念 / 直球判断 / 抱怨 / 困惑]

#### 主体（按 MECE 模块给骨架）
| 模块 | 让读者感觉到什么 | 必带的具体证据 | 语气/态度参考 |
|------|------------------|----------------|----------------|
| 模块1 | [一句话目标] | [截图/数据/对话引用] | [仅参考通过相关性门的作者在场正文候选] |
| 模块2 | ... | ... | ... |
| 模块3 | ... | ... | ... |

#### 收尾（线索版，不预写正文）
- 最后留给读者的一句立场: [一句立场，写手用自己的话说]
- CTA具体动作: [说什么 + 在哪做 + 为什么读者要做]
```

**硬规则**：
- 每条骨架 ≤ 80 字
- 不允许出现连续 3 行以上的"成品级"段落
- 必须留 voice 空间给写手——任何句子都可以被写手改写
- 发现整段预写正文时，当前 Agent 保留必要原稿并提取骨架后继续；不丢弃唯一内容，不执行逆向 stage 迁移

#### 反 AI 味检查清单（写入 `### 反AI味检查`，6 条硬规则）

```markdown
### 反AI味检查

- [ ] 1. 钩子从具体场景/具体数字/具体动作开始
      ❌ "很多人都以为..." / "我们常常忽视..." / "你是否..."
      ❌ 浏览器未登录 / 自动化停止 / Agent 调用等与主题无关的内部过程
      ❌ "整理素材时刷到..." / "真正让我停下来看的，是...的差别"
      ✅ "我把同样四个词喂给 GPT 两次" / "晚上11点我盯着屏幕"
      同时已和最近 5 篇开头做撞型检查，本篇不复用同一来源动作和句式骨架

- [ ] 2. 不出现书面分析腔
      ❌ 大纲里写"本文解决承诺" / "次要矛盾" / "主流解法" / "用户表面诉求" / "目标读者期待"
      ❌ 用"层" / "维度" / "路径" / "切口" / "链路"作主语
      ✅ 用"我" / "你" / "这件事" / "那张图"作主语

- [ ] 3. 不用机械转折
      ❌ "不是 A，而是 B" / "看似 A，实则 B" / "表面 A，深层 B" / "与其 A，不如 B"
      ✅ 直接说 B；或写"我以为 A，后来发现 B"

- [ ] 4. 作者立场自然可见，不靠配额制造人味
      通过与主题相关的选择、判断或具体细节体现作者
      不强制使用"我承认/我最烦/有点尴尬"，不写内部过程日志

- [ ] 5. 不用集体大词开头
      ❌ "我们都..." / "很多人会..." / "大家其实..." / "现在的人..."
      ✅ "我自己跑了三次才明白" / "我有个朋友上周问我"

- [ ] 6. 每个主体模块至少 1 个具体细节锚点
      时间 / 数字 / 动作 / 对话 / 物件 中至少 1 个
      纯抽象论述的模块视为不合格，必须补一个细节
```

**上述六项在 flagship 策划阶段完整执行；standard 在写作与审稿核验正文，不因策划未勾满而阻塞。**

4.  **Step 5: 确认大纲（含可信支撑记录 + 人味复核）**
    *   沿用用户已选方向；授权策划或成品且未保留终选权时自行选定、记录依据并完成修改。
    *   **可信支撑检查（确认大纲时记录，不强行写作）**：
        -   派活清单是否完整（截图 / 提示词 / 录屏 / 数据 / 亲历案例 / 对比样本至少有一类可用）
        -   执行者、取得方式和缺少的用户输入是否明确；不要求口头承诺
        -   如果用户说"我没法准备支撑"→ 建议：调整方向 / 降级为速发短篇 / 换一个有实操基础的选题
        -   `### Hook素材增补` 是否已经写清 Hook 模式、候选锚点、事实边界和未完成的获取动作
    *   **结构检查（必须通过）**：
        -   `### 主要矛盾` 是否只有 1 个主冲突
        -   `### 第二层思考` 是否说明了比"会用工具"更深一层的价值
        -   `### MECE拆解` 是否存在重复、漏项、同层混用不同拆法
        -   `standard` 只把主要矛盾和骨架边界作为门禁；`flagship` 三项都必须通过
    *   **作者在场与自然度复核（flagship 必须，standard 在写作后自检）**：
        -   `### 风格转译` 是否完整：调性档位、开头模式、开头候选、近 5 篇撞型检查、可用口语表达、**作者在场设计（正文候选 / 验证边界 / 内部过程日志三类分流，正文候选允许为 0）**、本篇禁用表达、正文语气基准、人格姿态自检全部填写
        -   `### 反AI味检查` 6 条是否全部勾选
        -   `### 内容结构` 是否每条骨架 ≤ 80 字、未出现连续 3 行成品级段落
        -   `flagship` 任一项不通过 → 不得进入 `planned`，必须先回到 Step 1.6 / Step 4 补完
    *   **更新 `## 内容策划` > `### 内容结构`**：写入正式大纲骨架（清理草案标记）。
    *   **更新 `## 内容策划` > `### 主要矛盾` + `### 第二层思考` + `### MECE拆解`**：写入确认后的最终版本。
    *   **更新 `## 内容策划` > `### 风格转译` + `### 反AI味检查`**：确认最终版本。
    *   **更新 `## 内容策划` > `### Hook素材增补`**：保留选定方向，淘汰无关候选，并把未完成取证同步到派活清单。
    *   **更新 `## 内容策划` > `### 派活清单`**：写入确认后的最终派活清单。
    *   教程类同时确认 `### 实测任务包` 已经能让用户直接开测；缺完整提示词或截图位置时，不得进入 `planned`。
    *   **更新 YAML**：`stage: planned`, `evidence_status: partial|missing`。
    *   *推进*：直接核验普通文章证据；教程类交付测试任务并执行可用的授权测试，确需用户提供输入时只暂停相关部分。

5.  **Step 6: 确认素材支撑（进入写作前）**
    *   用户要求确认素材、写作或交付成品时直接执行证据核验，不等待专用口令。
    *   检查 `### 派活清单` 是否至少有一类可信支撑已经可用：Demo、截图、录屏、提示词、数据、亲历案例、对比样本。
    *   检查 `### Hook素材增补`：
        -   `Hook可用状态：ready`
        -   `evidence / hybrid` 至少有 1 条 `verified` 锚点
        -   `opinion` 写清依据的原始素材和事实边界
        -   `candidate / missing` 仍可保留作后续素材，但不得被标为开头或标题可用
    *   教程类必须额外检查：
        -   `### 实测任务包` 中 `测试状态：ready`
        -   至少 3 项关键截图已勾选，或有等价的录屏、输出文件和日志证据
        -   `### 实测结果记录` 已填写实际结果、异常和可引用结论
        -   只有提示词、没有实际结果时保持 `planned`
    *   更新 `### 派活清单` 中的 `支撑状态：ready`。
    *   更新 YAML：`stage: assets_ready`, `evidence_status: ready`, `agent: viral-content-strategist`, `updated: [今天日期]`。
    *   *推进*：核验通过后，成稿任务直接写作；单独的素材确认任务报告核验结果即可。

## 派活清单：按内容类型的重点

> 详细模板见 [`参考资料/spec-work-templates.md`](参考资料/spec-work-templates.md)

| 内容类型 | 派活重点 | 提示词要求 |
|---------|---------|-----------|
| **教程类**（学习复现型） | 每步截图 + 完整提示词序列 + 预期结果 | 必须给出每一步的完整提示词，可直接复制 |
| **提示词清单类**（收藏复用型） | 场景分类 + 提示词模板 + 使用说明 + 示例结果 | 必须按场景整理成可复制模板，方便收藏 |
| **工具推荐类**（选择决策型） | 推荐名单 + 适用场景 + 不推荐原因 + 对比截图 | 必须给出选择标准，不能只罗列名称 |
| **测评类**（工具清单/对比型） | 统一测试提示词 + 对比维度表 + 每个工具截图 | 必须给出统一的测试提示词，确保公平对比 |
| **避坑类**（避坑吐槽型） | 错误操作截图 + 正确操作截图 + 错误/正确提示词对比 | 给出错误提示词和修正后的提示词 |
| **展示类**（造物展示型） | 成品截图/录屏 + 关键步骤截图 + 核心提示词 | 给出制作过程中的关键提示词 |
| **热点类**（热点结合型） | 热点截图 + 自己的实操验证截图 + 验证提示词 | 给出用来验证热点功能的提示词 |
| **方法论案例类**（IP沉淀型） | 框架图 + 真实案例 + 关键判断点 + 复盘 | 必须交付可复用判断框架，不只讲故事 |

### 教程类实测任务包最低交付

1. 测试媒介与唯一主变量
2. 可直接复制的完整提示词
3. 关键参数与输入素材
4. 预期结果与失败信号
5. 至少 7 个具体截图位置
6. 实测结果记录区，初始状态为 `missing`

提示词和截图格式以 [`参考资料/spec-work-templates.md`](参考资料/spec-work-templates.md) 为准。

### 同素材不同角度的策划要求

- `content_angle: tutorial`：大纲重点放在步骤顺序、卡点、复现路径
- `content_angle: prompt_list`：大纲重点放在分类体系、模板结构、适用场景
- `content_angle: tool_list` / `comparison`：大纲重点放在推荐逻辑、选择标准、适合谁
- `content_angle: methodology` / `case`：大纲重点放在方法论、判断框架、案例复盘

如果 YAML 已明确 `content_angle`，策划师不得擅自改成别的形态，除非先提示用户当前角度不成立。
