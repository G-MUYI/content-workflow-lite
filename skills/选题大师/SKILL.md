# 选题大师 (Topic Master)

> 规则边界：本文是执行卡。状态机、迁移白名单、完成判定以 `../../AGENTS.md` 与 `../../scripts/workflow_config.py` 为准。

> **核心策略：收件箱优先 (Inbox First)**
> 收到素材 = 立即保存。先落库，再分析。

---

> 协作边界：自主选择、澄清、批准和完成统一按 `../../AGENTS.md` 的“自主执行、澄清与完成”；下文步骤不构成逐步审批，职责切换由当前 Agent 完成。

## 文件模板

默认使用 `选题库/_模板/选题模板-标准.md`。只有用户明确选择 `workflow_mode: flagship` 时使用完整模板 `选题库/_模板/选题模板.md`。inbox 阶段只填写 YAML + `## 原始素材`。

## ⚡ 自动保存流转逻辑

### 场景 1：新素材处理 (Inbox Entry)

**当用户提供用于内容生产或素材整理的素材时执行；审阅对象、普通问答或报错不自动入库。处理素材：**

1.  **Step 1: 立即建档**
    *   YouMind 采集只读「灵感收集」项目，先运行 `python scripts/youmind-added-time.py` 由 `source_id` 解码并核实添加时间排序。
    *   YouMind 采集先按 `../_通用/每日来源评分.md` 跳过已确认的自建空文件；它们不算素材、不建档、不占来源名额，继续向后补足。
    *   在 `选题库/_inbox/` 基于统一模板创建新文件。
    *   文件名：`YYYY.MM.DD-[类型]-[关键词].md`
    *   **写入 YAML**：
        ```yaml
        ---
        title: "素材描述"
        status: "todo"
        stage: "raw_idea"
        agent: "topic-master"
        source: "来源"
        source_type: "链接"
        created: [今天日期]
        updated: [今天日期]
        source_id: "[同素材簇ID]"
        workflow_mode: "standard"
        timeliness_level: ""
        recommended_path: ""
        content_angle: ""
        content_goal: ""
        content_form: ""
        target_platforms: []
        primary_platform: ""
        brief_audience: ""
        brief_user_action: ""
        brief_core_promise: ""
        brief_seed_sharer: ""
        brief_share_recipient: ""
        brief_share_message: ""
        evidence_status: "missing"
        ---
        ```
    *   **填充 `## 原始素材` 区块**：写入用户发送的内容。其余 section 保留模板占位。
    *   *告诉用户*："已保存到 Inbox，正在分析..."

2.  **Step 2: 按事实与时效缺口补充检索**
    *   使用当前可用的联网检索工具核验外部事实和相关讨论；复用仍有效的原始来源，纯个人经历或素材整理不强制做竞品全景搜索：
        *   搜索关键词：素材核心概念 + "教程"/"技巧"/"提示词"/"清单"/"推荐"/"对比"
        *   目标：了解当前热度、已有内容角度、信息缺口
    *   **记录搜索发现**到 `## 市场调研` > `### 初步扫描` 区块：
        *   全网热度：有多少人在讨论
        *   已有角度：别人都在写什么
        *   信息缺口：哪些角度还没人写
        *   时效性判断：是否还有写的价值
    *   *告诉用户*："正在搜索全网相关内容..."

2.5. **Step 2.5: 先判时效，再判路径（必须执行）**
    *   **先判断是否为强时效素材**：满足以下 4 条中的 2 条及以上，判定为强时效
        *   热度窗口预计 ≤ 72 小时
        *   讨论正在快速上升
        *   晚 3-7 天发，价值会明显衰减
        *   已经有一个可先发的明确判断
    *   **如果是强时效素材**：
        *   默认推荐路径：`short_post_first`
        *   更新 YAML：`workflow_mode: quick`, `timeliness_level: strong`, `recommended_path: short_post_first`, `content_form: short_post`
        *   在 `### 判断模块` 中明确写：先速发，后续再裂变成长文
    *   **如果不是强时效素材**：
        *   比较 `观点文` 和 `实用文` 两个方向谁更强
        *   观点文信号：有鲜明判断 / 有个人案例 / 重在认知刷新 / 缺可信立场
        *   实用文信号：能沉淀步骤/模板/名单/表格 / 用户更想收藏 / 用户更想决策
        *   若实用文更强，再继续细分：`tutorial` / `prompt_list` / `tool_list` / `comparison`
        *   更新 YAML：`timeliness_level: medium|weak`, `recommended_path: [最终路径]`
    *   **填充 `## 选题评估` > `### 判断模块`**：
        *   时效判断
        *   推荐路径
        *   判断原因（2-3条）
        *   备选裂变
        *   若推荐路径为 `tutorial`：额外写明 `测试媒介` 和 `可实测性`，确认是否能生成可直接复制的测试提示词、是否能取得截图或等价证据

2.6. **Step 2.6: 第二层思维校验（必须执行）**
    *   **不只问“这篇会讲什么”，还要问“用户因此会少走什么弯路”**。
    *   对主推角度至少补全以下 4 项：
        *   第一层会写什么：工具 / 技巧 / 案例 / 流程本身
        *   第二层真正价值：减少什么成本、风险、试错、决策压力
        *   反直觉切口：与主流写法相比，哪里更值得写
        *   为什么值得现在写：窗口期 / 信息差 / 决策价值 / 方法论价值
    *   **填充 `## 选题评估` > `### 第二层思考`**。
    *   **执行规则**：
        *   如果一个角度只有第一层，没有第二层价值，不得评为 S / A 级主推角度
        *   如果多个角度都能做，优先推荐第二层价值更强的那个
        *   如果素材本身很热，但第二层价值薄弱，明确提醒用户“能追热点，但沉淀价值一般”

2.7. **Step 2.7: 多来源候选评分（有 2 条及以上来源时必须执行）**
    *   读取 [`../_通用/每日来源评分.md`](../_通用/每日来源评分.md)。
    *   YouMind 来源先按其「采集范围与添加时间核实」确定最新 5 条；脚本核实未通过时停止，不用更新时间或列表位置代替。
    *   先按 `duplicate / private_only / source_inaccessible` 做硬排除，不让重复稿、私人材料或不可读来源参与 Top 1。
    *   模型只为每条来源填写 5 个 0–10 子分和一句证据理由：受众需求匹配、信息增量、可交付价值、证据可写性、时效窗口。
    *   把候选写成 JSON，运行 `python scripts/rank-daily-sources.py --input <json> --format markdown`；不得在模型侧自行改权重、信源修正、路径门槛或并列规则。
    *   将脚本输出写入 `## 选题评估` > `### 来源候选评分`，保留所有候选的子分、信源等级、总分、排除原因和 Top 1。
    *   没有候选达到门槛时，结论必须是“今天不强行出稿”，保持来源记录，不为完成任务降低门槛。

3.  **Step 3: 分析并生成候选项**
    *   基于素材与必要核验生成候选；通常 3-5 个，已有明确方向或速发任务只补有意义的比较，不为数量扩写。
    *   **旗舰模式做完整 HKR 预筛**：
        *   读取 [`../_通用/HKR选题质检.md`](../_通用/HKR选题质检.md)
        *   对主推角度分别评估：H 好奇感 / K 信息量 / R 共鸣感
        *   如果只有 1 项高分，不得直接评为 S / A，必须先提示补素材、换角度或降级为后续裂变
        *   把结果写入 `## 选题评估` > `### HKR质检`
    *   **同素材多角度检查（必须执行）**：
        *   优先尝试覆盖至少 2 类不同内容角度：教程型 / 提示词清单型 / 工具推荐型 / 方法论案例型
        *   不再默认"一个素材只产出一个选题"
        *   如果同素材有 2 个及以上 A 级以上角度，必须同时保留：`主推角度` + `裂变角度`
    *   **填充 `## 选题评估` 区块**：
        *   `### 判断模块`：先给出结论，不允许只列候选不下判断。
        *   `### 第二层思考`：明确主推角度的第一层 / 第二层 / 反直觉切口。
        *   `### HKR质检`：仅 `flagship` 必填；standard 可写一句简评。
        *   `### 候选选题`：写入各选题方向及简要分析。
        *   `### 角度矩阵`：写清每个角度对应的用户动作、核心交付、可收藏性、时效性、是否独立成篇。
        *   `### 7维度评估`：仅 `flagship` 必填，标准与等级只读取 `_通用/爆款核心定义.md`。
    *   **质量判断**：`standard` 用需求、交付、证据三项快速判断；`flagship` 才执行完整 7维评分。
    *   **多来源例外**：无论 workflow_mode，只要本轮比较 2 条及以上来源，就必须执行 Step 2.7；该评分用于选来源，不能拿旗舰 7维评估替代。
    *   **更新 YAML**：`stage: topics_generated`
    *   *告诉用户*："分析完成，为您生成了以下选题方向（已保存）：..."

4.  **Step 4: 确认入库**
    *   用户已指定则沿用；授权成品或自动入库时模型选定主推角度并记录依据，明确保留人工选择权时才等待。
    *   **移动文件**：从 `_inbox/` 移动到 `待写/`。
    *   **重命名**：`[等级]-[打断要素]-[正式标题].md`
    *   **更新 YAML**：`stage: checked_in`, `title: [正式标题]`, `priority: [等级]`, `interrupt_type: [打断要素]`, `content_angle: [角度类型]`, `content_goal: [目标]`, `recommended_path: [最终路径]`
    *   **写入标准化 `## 内容Brief`**，并同步 YAML：
        *   `brief_audience`：这篇明确写给谁
        *   `brief_user_action`：读者看完后要做什么
        *   `brief_core_promise`：标题和正文共同承诺什么结果
        *   如果 `content_goal: growth`，额外填写传播入口：
            -   `brief_seed_sharer`：第一批最可能主动转发的人，不写“所有读者”
            -   `brief_share_recipient`：他们会转发给谁
            -   `brief_share_message`：转发者借这篇内容想表达“我懂什么 / 我支持什么 / 我在帮谁 / 我发现了什么”
        *   `primary_platform`：主发布平台
        *   `evidence_status: missing`：等待策划阶段补齐可信支撑
        *   `主要证据`：Demo / 截图 / 数据 / 亲历案例 / 对比样本
        *   `不写边界`：这篇不碰哪些方向，避免后续跑题
    *   **同素材去重规则**：
        *   若已存在相同 `source_id` + `content_angle` 的文件 → 更新原文件，不新建
        *   若 `source_id` 相同但 `content_angle` 不同 → 允许创建兄弟选题
    *   **更新 `## 选题评估`**：保留选中的选题信息，清理未选的候选项。填写 `### 核心洞见`，并保留已确认的 `### 第二层思考`。

## 同素材多角度判断规则

> 判断重点看用户能拿走什么价值，不看素材表面像什么。

| 角度 | 适合什么时候主推 | 用户会因为什么收藏/转发 | 最强交付 |
|------|----------------|-------------------------|---------|
| **教程型** | 新工具窗口期、用户强烈想上手 | 看完能马上复现 | 步骤、截图、完整流程 |
| **提示词清单型** | 素材中可沉淀出可复用模板 | 想保存备用，反复查阅 | 提示词、模板、清单 |
| **工具推荐型** | 用户核心问题是"用哪个" | 节省试错成本 | 推荐名单、对比表、适用场景 |
| **方法论/案例型** | 你有独特系统或真实作品 | 认知被刷新，记住你 | 框架、案例、复盘 |

### 快速判断口诀

- 用户想**马上做出来** → 优先教程型
- 用户想**先收着以后抄** → 优先提示词清单型
- 用户想**别踩坑、少试错** → 优先工具推荐型
- 用户想**知道你是怎么想的** → 优先方法论/案例型

教程型只有在以下两项都成立时才能作为主推：

1. 能明确判断测试媒介，并交给策划师生成可直接复制的测试提示词
2. 用户或已授权的自动化能够取得关键步骤截图、输出文件或等价证据

暂时无法取得实测结果时，可以先入库并推进到 `planned`，但要在判断模块明确写出缺口，不得承诺已经复现。

### 什么时候直接建议做速发短篇

满足以下 3 条中的 2 条，就优先建议 `short_post`：

1. **强时效**：热点窗口期预计 ≤ 72 小时
2. **单点表达清晰**：一句话就能说清核心判断
3. **最小实证已具备**：至少有一个例子 / 一个截图结论 / 一个观察

此时选题大师应明确给出建议：

- `先发短篇`：300-500字，抢时效
- `后续裂变`：再扩成长文 / 清单 / 方法论

推荐同时更新 YAML：

- `content_form: short_post`
- `target_platforms: [x, 朋友圈, wechat]`（按用户目标调整）

## 素材判断模块

> 每次选题前，必须执行这个顺序：`先判时效 → 再判轨道 → 最后判具体形态`

### 第一层：时效判断

| 判断问题 | 是 | 否 |
|---------|----|----|
| 这个话题 72 小时后会明显失去时效价值吗？ | 加强强时效信号 | 不加分 |
| 现在讨论量是否在上升？ | 加强强时效信号 | 不加分 |
| 晚几天发会不会失去优势？ | 加强强时效信号 | 不加分 |
| 我现在是否已有一句可先发的判断？ | 可先速发 | 需要继续判断长文形态 |

结论：满足 2 条及以上 → `强时效素材`

### 第二层：轨道判断

- **观点文轨道**：更适合“认知刷新、态度判断、个人洞察”
- **实用文轨道**：更适合“步骤、模板、清单、推荐、对比”

### 第三层：具体形态判断

| 路径 | 什么时候优先选它 |
|------|----------------|
| `opinion` | 你的判断比信息本身更有价值 |
| `tutorial` | 用户最想马上学会、马上复现 |
| `prompt_list` | 用户最想收藏、复制、反复查 |
| `tool_list` | 用户最想知道选哪几个 |
| `comparison` | 用户最想知道 A 和 B 怎么选 |

### 最终输出要求

每次都必须明确说：

1. 这是不是强时效素材
2. 最推荐哪条路径
3. 为什么不是另外几条路径

### Seedance 类素材的标准处理

同一份 Seedance 素材，通常至少可裂变为：

1. 教程型：从 0 到 1 跑通
2. 提示词清单型：可直接复制的镜头/动作/风格提示词
3. 工具推荐型：Seedance 适合谁，不适合谁，和替代工具怎么选
4. 方法论型：如何把零散技巧整理成稳定出片流程

仅要求候选时排序交付；授权成品时选择最强角度继续，不自动扩写所有裂变方向：

- **这次先做**：当前最强角度
- **后续可裂变**：另存为兄弟选题

### 场景 2：整理选题库 Inbox

**当用户说 "整理inbox" 时：**

1.  仅扫描 `选题库/_inbox/` 下 `stage: raw_idea` 的文件。
2.  逐个进行 **Step 2** 的分析操作。
3.  如果用户这次要处理的是 `素材库/提示词/_inbox/`，先由提示词整理师完成资产整理，再接收其创建的关联选题副本；副本应带 `recommended_path: prompt_list`、`content_angle: prompt_list`，然后继续执行 Step 2。
4.  如果用户这次要处理的是其他 `素材库/**/_inbox/`，不由本 Skill 直接处理，先转交知识园丁；只有知识园丁明确判定适合写成内容选题时，再创建关联选题副本。

## 人设合规速查

> 详见 [`../_通用/创作者定位.md`](../_通用/创作者定位.md)
