# 分级扩张批处理合同

> 适用于批量整理历史文章、迁移字段、拆内容单元、重建素材关系等同构历史数据变换；少量相关规则、代码和测试的维护不套用本批处理流程。

## 核心顺序

```text
L0 只读审计 → L1 小样本 → L2 验证 → L3 分批扩张 → L4 收尾
```

未完成前一层验证不得进入下一层；用户已授权范围内由当前 Agent 验证后连续推进，不逐层请求批准。

## L0：只读审计

必须输出：

- 精确目标目录、文件数和文件类型。
- 当前 schema 分布、缺失字段、重复项、异常文件。
- 预期改动、不会改动的内容、回滚依据。
- 小样本名单和验收标准。

运行：

```bash
python scripts/plan-batch-expansion.py --target "<目标目录>"
```

L0 不修改目标内容。

## L1：小样本

- 默认取 `min(5, 向上取整(总量 × 10%))`，至少 1 个。
- 样本必须覆盖主要结构变体和至少 1 个异常边界，不只挑最整齐的文件。
- 只修改清单中的显式文件，不使用未解析 glob 扩大范围。
- 保存样本前后差异和失败项。

## L2：验证

至少通过：

1. 结构校验无新增错误。
2. 相关单元测试和行为评测通过。
3. 样本中的来源、正文和历史数据未被误删。
4. 新字段能被下游 Skill 正确读取。
5. 发现结构性问题时停止并修改方案，不用增加兼容分支掩盖。

只有验收结论明确为“通过”，才能进入 L3。

## L3：分批扩张

- 每批最多 20 个文件，或剩余文件的 25%，取较小值。
- 每批结束重新运行与 L2 相同的验证。
- 连续出现 2 个同类错误、任一数据丢失、范围漂移或错误数增加时立即停止。
- 已完成批次、未处理批次和失败清单分开记录。

## L4：收尾

输出：

- 总处理量、成功量、跳过量、失败量。
- schema 版本或规则变化。
- 验证命令与结果。
- 遗留问题。
- 回滚或恢复依据。

## 权限边界

- 用户说“批量整理”授权的是所指目录和处理目标，不自动授权删除、覆盖原始材料或跨目录清理。
- 删除、合并移除原文件、改变已发布正文或重写历史数据需要对应授权；已明确授权相同动作与边界时保全唯一内容后执行，不重复确认。
- 工作区已有未提交改动时，批处理必须保留并绕开无关变更。
