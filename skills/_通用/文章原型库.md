# 文章原型库

> 用途：策划和写作前先判断文章属于哪种原型。原型决定证据怎么准备、开头怎么切、正文怎么展开。原型是辅助判断，不替代 `content_angle` 和 `recommended_path`。

## 原型一：调查实验型

**适合**：你亲自试了一个东西、验证了一个传闻、踩了一个坑。

**核心承诺**：我替你去做了，结果是这样。

**必须有的支撑**：
- 过程截图或录屏
- 关键步骤
- 意外发现
- 真实感受和失败点

**常见结构**：为什么想试 -> 怎么试 -> 发生了什么 -> 哪里出乎意料 -> 给读者的判断。

## 原型二：产品体验型

**适合**：新工具、新功能、新模型、新平台体验。

**核心承诺**：我带你看它真实用起来是什么感觉。

**必须有的支撑**：
- 具体使用场景
- 实测结果
- 和替代工具的自然对比
- 适合谁和不适合谁

**常见结构**：场景开头 -> 功能体验 -> 亮点 -> 槽点 -> 选择建议。

## 原型三：现象解读型

**适合**：一个热点、一个刷屏现象、一个行业变化。

**核心承诺**：这件事表面热闹，背后真正值得看的是这里。

**必须有的支撑**：
- 现象截图或案例
- 多平台讨论证据
- 一个能把现象讲深的解释框架
- 和普通写法不同的判断

**常见结构**：现象 -> 为什么大家关注 -> 更深的问题 -> 你的判断 -> 对读者有什么影响。

## 原型四：工具分享型

**适合**：推荐一个工具、提示词、模板、流程。

**核心承诺**：我发现一个能帮你省事的东西，并告诉你怎么用。

**必须有的支撑**：
- 使用前后的对比
- 可复制步骤或提示词
- 适用边界
- 常见失败点

**常见结构**：真实需求 -> 工具出现 -> 演示效果 -> 具体用法 -> 适合收藏的清单。

## 原型五：方法论案例型

**适合**：沉淀你的做事方法、判断框架、复盘经验。

**核心承诺**：我把这件事背后的方法讲清楚，你可以迁移到自己的场景。

**必须有的支撑**：
- 一个真实案例
- 可复用框架
- 判断标准
- 学习成本和局限

**常见结构**：一个真实问题 -> 我的做法 -> 框架抽象 -> 案例验证 -> 读者怎么套用。

## 原型六：教程清单型

**适合**：用户最想收藏、跟做、复制。

**核心承诺**：照着做，能拿到一个具体结果。

**必须有的支撑**：
- 步骤
- 截图位置
- 完整提示词或参数
- 常见问题

**常见结构**：效果展示 -> 准备工作 -> 步骤 -> 常见问题 -> 一页清单。

## 选择规则

| 如果主要价值是 | 优先原型 |
|----------------|----------|
| 亲自验证真假 | 调查实验型 |
| 体验新工具 | 产品体验型 |
| 解释热点 | 现象解读型 |
| 分享可用工具 | 工具分享型 |
| 沉淀认知框架 | 方法论案例型 |
| 教读者做出来 | 教程清单型 |

策划时写入 `## 内容策划` > `### 文章原型`（独立 section，不要塞进 `### 内容结构` 里）：

```markdown
### 文章原型

- **原型**：产品体验型
- **选择原因**：这篇的价值不是罗列功能，而是让读者知道真实用起来是否值得投入。
- **该原型必须准备的证据**：[列出截图/数据/录屏/对比样本等具体清单]
```
