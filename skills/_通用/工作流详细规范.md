# 内容创作工作流详细规范

> 本文件保存完整业务规则，供修改工作流、处理边界情况和审计时按需读取。日常启动只加载根目录 `AGENTS.md`；机器可判的字段、状态与迁移以 `scripts/workflow_config.py` 为准。

## 语言

所有回复使用简体中文。

## 终端

Bash 工具的底层 shell 是 Git Bash。
- 直接使用 bash 命令（ls、find 等），不要套 cmd.exe
- 中文路径使用双引号包裹
- 工具入口只能使用 PowerShell 时，仅用它启动 Git Bash，不用于读取或处理文件编码

---

## 开局协议

触发范围与展示方式以 `AGENTS.md` 为准。运行 `python scripts/run-opening-protocol.py` 一次，使用脚本的仪表盘口径，不在模型侧重复计算。

脚本失败时，先读取会话记忆和用户偏好，再按当前任务需要扫描相关内容目录；将不可得的统计标为暂缺，不手算另一套仪表盘。告警不替换用户任务，不依赖扫描的工作继续。

## 执行边界

自主性、澄清、批准和完成条件统一读取 `AGENTS.md` 的“自主执行、澄清与完成”。本文和执行卡中的“确认”均按该节判断，不强制多一轮对话；方法检查按工作流模式适用，真实结果与合法迁移仍是硬门禁。

## 自动化学习系统（后台运行）

> **核心原则**：学习应该是无感的，AI 在后台自动观察、记录、学习，不打扰用户。

### 对话进行中（自动触发）

- 情绪只用于调整回复长度与询问频率，静默更新 `用户偏好.md`。
- 用户明确表达长期偏好时立即记录并用一句话确认；一般修改先记入 `反馈记录.md`。
- 同类修改累计 3 次或用户明确说“记住”时，沉淀到 `我的风格.md`，并从待观察记录中移除。
- 方案选择、方向确认和临时偏好写入 `会话记忆.md`；不得记录敏感信息或凭空推断。
- 用户明确说某个方向“不做 / 不要 / 不再提”时，立即写入 `## 用户已否决的方向`，记录适用范围、否决依据和可重提条件。未满足可重提条件时不得再次默认推荐。
- 尚未证实但值得测试的判断写入 `## 待验证假设`，状态使用 `candidate / testing / verified / rejected`。`candidate / testing` 不得写成事实、长期偏好或已确认决策。

### 对话结束时（自动触发）

用户说“先这样 / 暂停”或任务自然结束时，更新当前任务、关键决策、临时偏好、未完成事项和本周学习摘要。只保留当前状态与最近决策，避免把运维说明、示例模板持续追加进动态文件。

### 学习系统可观测性（新增）

“查看我的风格档案 / 我的偏好”读取用户偏好、我的风格和最近 10 条反馈；“本周学到了什么”只展示本周新增偏好、仍在观察的修改模式和已沉淀规则。无新增时明确显示“本周暂无新学习内容”。

### 手动触发（保留，但不强调）

保留“记录这次反馈”“记住这个偏好”“上次说到哪了”“暂停自动学习”“恢复自动学习”；默认开启自动学习。

## 状态机与自动保存

> **核心原则：积极保存 (Eager Save)** — 任何生成工作开始前或完成后，必须先写入文件。确保"所见即已存"，杜绝中间状态断档。

### 统一模板

默认使用精简模板 `选题库/_模板/选题模板-标准.md`；只有 `workflow_mode: flagship` 才使用完整模板 `选题库/_模板/选题模板.md`。新素材先填写 YAML + `## 原始素材`，其他区块随阶段逐步补齐，避免 raw idea 背负完整发布壳。

### YAML 结构标准

```yaml
---

priority: ""                   # S / A / B / C
interrupt_type: ""             # 意外 / 相关 / 紧迫
source: ""
source_type: ""                # 经历 / 文章 / 想法 / 截图 / 链接 / 对话
source_id: ""
workflow_mode: "standard"      # quick / standard / flagship
timeliness_level: ""           # strong / medium / weak
recommended_path: ""           # short_post_first / opinion / tutorial / prompt_list / tool_list / comparison / methodology
content_angle: ""              # tutorial / prompt_list / tool_list / comparison / methodology / case
content_goal: ""               # growth / collect / decide / trust
content_form: ""               # article / short_post / x_thread / xiaohongshu_card / video
target_platforms: []
primary_platform: ""
brief_audience: ""             # 内容Brief：目标读者
brief_user_action: ""          # 内容Brief：读者看完后的动作
brief_core_promise: ""         # 内容Brief：标题/正文共同承诺
brief_seed_sharer: ""          # growth 必填：第一批谁会转发
brief_share_recipient: ""      # growth 必填：转发给谁

```

### 工作流模式

| 模式 | 默认用途 | 硬门禁 |
|------|---------|-------|
| `quick` | 强时效短篇、X、朋友圈、公众号短文 | 角度确认、最小实证、短稿结构、发布风险 |
| `standard` | 默认文章、教程、清单、普通公众号长文 | 内容Brief、主要矛盾、内容结构、关键证据、风格自检、发布风险 |
| `flagship` | 用户明确要求深度打磨的重点内容 | 标准模式全部要求 + HKR、7维、完整风格转译、第二层思考、MECE、证据账本、信息充分性检查、反AI味策划检查 |

执行原则：

1. `short_post` 或 `short_post_first` 自动视为 `quick`。
2. 未填写 `workflow_mode` 的历史文件按 `standard` 处理。
3. S 级不自动等于 `flagship`；只有用户明确要求深度打磨时才升级，避免把每篇文章都做成重流程。
4. 市场调研在 `standard` 中按需执行，在 `flagship` 中默认执行。
5. 风格档案始终是正文约束；旧的 5 项私人锚点问卷已废弃。`standard` 不要求在策划前完成完整风格转译表，写作后的风格自检与审稿核验仍是硬门禁。

### 状态合法迁移白名单

只允许以下迁移路径；后续交付请求包含补齐必要前置，不执行未登记的直接跳转：

```
raw_idea → topics_generated → checked_in → market_researched → strategies_generated → planned → assets_ready → drafted → titled → reviewed → published
任意 stage → archived（弃用）
```

**可选跳过**：
- `checked_in` → `strategies_generated`（跳过市场调研）

**禁止假跳步**：在 `checked_in` 收到成稿请求，先自行完成必要策划、定稿与证据核验，再逐步进入写作。在 `planned` 收到写作请求，直接核验并补充素材；仅在缺少无法自行取得的关键证据时暂停依赖的写作。

**条件例外**：`checked_in` → `drafted` 不是普通白名单迁移，只能在以下任一条件成立时执行：
- YAML `workflow_mode: quick`
- YAML `content_form: short_post`
- YAML `recommended_path: short_post_first`
- 用户明确说"快速出稿" / "速发" / "发个短的"

执行该条件迁移时，`## 内容策划` 可留空，但必须在 `## 写作笔记` 标注"快速出稿模式，跳过策划"或"速发短篇模式，跳过完整策划"。

### 同素材多角度规则（新增）

> **核心原则：一个素材，不等于只能写一篇。**

同一份原始素材，如果满足以下任一条件，应视为**不同内容角度**，允许拆成多篇独立选题：

1. **用户动作不同**：看完后用户要做的动作不同
   - 教程型：立刻跟做
   - 提示词/清单型：先收藏，之后复用
   - 工具推荐/对比型：帮助决策，减少试错
   - 方法论/案例型：建立认知，强化IP

2. **核心交付不同**：文章交付物不同
   - 教程型交付：步骤 + 截图 + 过程
   - 提示词/清单型交付：模板 + 提示词 + 检查清单
   - 工具推荐型交付：推荐名单 + 对比表 + 适用场景
   - 方法论型交付：判断框架 + 真实案例 + 复盘

3. **标题承诺不同**：标题承诺的收益不同
   - "教你做出来" ≠ "给你现成模板" ≠ "帮你选工具" ≠ "告诉你为什么"

#### 角度选择优先级

当同素材可拆出多个强角度时，按目标决定优先做哪篇：

| 目标 | 优先角度 | 判断信号 |
|------|---------|---------|
| 抢热点、拉新 | 教程型 / 学习复现型 | 新工具窗口期强、需求验证高、步骤可复现 |
| 冲收藏 | 提示词清单型 / 模板型 | 可直接复制、用户会反复查阅 |
| 帮决策 | 工具推荐型 / 对比型 | 用户常问"哪个好"、"怎么选" |
| 建IP | 方法论型 / 案例复盘型 | 你有独特系统、真实作品、可形成认知标签 |

#### 文件去重规则

1. **同 `source_id` + 同 `content_angle`**：视为同一篇，更新原文件，不新建。
2. **同 `source_id` + 不同 `content_angle`**：允许新建为兄弟选题。
3. **已发布后再做裂变角度**：新建兄弟选题，不能复用原发布文件充当待写文件。
4. **同素材多篇并存时**：必须在 YAML 中写明 `source_id` 与 `content_angle`，避免仪表盘误判为重复稿。

#### 选题大师执行要求

选题大师生成候选项时，如果素材足够，必须至少尝试覆盖以下 3 类角度中的 2 类：

- 学习复现型（教程）
- 提示词/模板型（收藏）
- 工具推荐/对比型（决策）
- 方法论/案例型（IP）

若其中有 2 个及以上角度都达到 A 级及以上，不得强行只保留 1 个，必须明确标注：

- 主推角度（这次先做）
- 裂变角度（后续可继续做）

### 提示词素材双轨规则（新增）

> **核心原则：提示词既是可复用资产，也可能是文章选题。不能因为它被识别为提示词资产，就从写文章流程里消失。**

当用户投喂的是提示词、提示词集、提示词模板、提示词工作流，或用户说"整理素材"时被识别为提示词素材，必须执行双轨处理：

1. **资产轨**：保存/整理到 `素材库/提示词/`，使用提示词资产 schema（`collected → organized`）。
2. **选题轨**：同步在 `选题库/_inbox/` 创建或更新一份关联选题文件，`stage: raw_idea`，`recommended_path: prompt_list`，`content_angle: prompt_list`。
3. **关联规则**：两边必须使用相同 `source_id`；提示词资产 YAML 记录 `content_handoff: done` 与 `content_handoff_file: "选题库/_inbox/xxx.md"`。
4. **去重规则**：如果已存在相同 `source_id + content_angle: prompt_list` 的选题文件，更新/引用原文件，不新建。
5. **唯一跳过条件**：只有用户明确说"只入库提示词，不做文章"或资产 YAML 写 `content_handoff: skipped`，才可以不转交选题大师。

执行顺序：

```
提示词素材 → 提示词整理师入库 → 生成/更新关联选题 raw_idea → 选题大师生成候选选题
```

注意：提示词资产文件本身不移动到 `选题库/`，但必须生成一份面向写作流程的选题副本，防止素材库吞掉写作入口。

### 速发短篇模块（新增）

> **适用场景**：素材时效性强，需要在 30 分钟内完成可发布内容，优先发 `X`、`朋友圈`、`公众号短文` 等短篇渠道。

#### 定义

- **内容形态**：`short_post`
- **推荐字数**：`300-500` 字
- **目标**：抢时效、抢表达权、抢第一波互动，不追求一次写成深度长文
- **适合平台**：`x` / `朋友圈` / `公众号短文` / `即刻`

#### 与普通长文的区别

| 维度 | 速发短篇 | 普通长文 |
|------|---------|---------|
| 字数 | 300-500字 | 800字以上 |
| 核心目标 | 先发出去，占位表达 | 系统讲清楚，沉淀方法论 |
| 结构 | 1个钩子 + 1个观点 + 1个例子 + 1个收尾 | 完整开头、主体、结尾 |
| 是否需要完整策划 | 可跳过 | 通常需要 |
| 是否强依赖Demo | 弱依赖，可用最小实证 | 更依赖完整截图/案例 |

#### 启动条件

满足任一条件即可进入速发短篇模式：

1. 用户明确说：`速发` / `短篇速发` / `先发个短的`
2. 选题时效性强，且用户目标是抢窗口期
3. 用户明确指定平台：`X` / `朋友圈` / `公众号短文`

#### 最小流程

`raw_idea → topics_generated → checked_in → drafted`

说明：
- 先确定角度并记录依据，再进入 `checked_in`；已授权成稿时可由模型完成选择
- 进入速发短篇模式后，可跳过市场调研和完整策划
- 在 `## 写作笔记` 记录：`速发短篇模式，跳过完整策划`

#### 交付结构

速发短篇正文必须包含以下 4 个部分：

1. **钩子**：一句话抓住注意力
2. **核心观点**：你要表达的判断
3. **最小实证**：一个例子 / 一次观察 / 一个截图结论
4. **收尾动作**：引导收藏、转发或评论

#### 平台适配规则

| 平台 | 写法重点 | 建议长度 |
|------|---------|---------|
| `X` | 观点更锋利，句子更短，开头更像判断 | 150-300字 |
| `朋友圈` | 更像真人分享，减少说教感 | 200-350字 |
| `公众号短文` | 保留完整起承转合，可稍微展开 | 300-500字 |
| `即刻` | 轻观点 + 轻信息 + 轻互动 | 150-300字 |

#### 速发后的处理

1. 先发布短篇，占住时效
2. 如反馈好，再裂变为：
   - 长文教程版
   - 提示词清单版
   - 方法论复盘版
3. 裂变后的长文必须新建兄弟选题，不覆盖速发短篇原稿

### 素材判断模块（新增）

> **核心原则：先判断时效，再判断形态。**

收到任何素材后，必须先执行以下判断，而不是直接进入某一种写法。

#### Step 1：判断是否为强时效素材

满足以下 4 条中的 **2 条及以上**，判定为 `强时效素材`：

1. **窗口期短**：预计热度窗口 ≤ 72 小时
2. **讨论正在上升**：该话题刚爆、刚更新、刚发布、刚出新功能
3. **价值衰减快**：晚 3-7 天发，信息优势会明显下降
4. **单点表达已成立**：哪怕还没整理成长文，也已有一个明确判断可先发

#### Step 2：若是强时效素材

直接走：`速发短篇优先`

- 当前交付：`300-500字 short_post`
- 目标：先抢时效，先占表达权
- 后续动作：保留原素材，等反馈后再裂变成长文
- 推荐 YAML：
  - `timeliness_level: strong`
  - `recommended_path: short_post_first`
  - `content_form: short_post`

#### Step 3：若不是强时效素材

进入 `形态对比判断`，比较以下两大方向：

1. **观点文轨道**：适合输出判断、洞察、立场、方法论
2. **实用文轨道**：适合输出教程、清单、工具集合、对比、模板

#### Step 4：观点文 vs 实用文 评分规则

##### A. 观点文更优的信号

满足越多，越适合做观点文：

1. 你有鲜明判断，不只是信息搬运
2. 你有亲身经历、案例、踩坑或独特视角
3. 这类内容的核心价值是“让人重新理解”，不是“照着操作”
4. 同类信息已经很多，但缺少一个可信的立场

##### B. 实用文更优的信号

满足越多，越适合做教程 / 清单 / 集合 / 对比：

1. 用户看完后最想做的是“保存下来以后用”
2. 素材可以沉淀成步骤、模板、提示词、名单、表格
3. 用户常见问题是“怎么做”“用哪个”“有没有现成的”
4. 信息整合本身就有价值，哪怕观点不强也能成立

#### Step 5：实用文内部再细分

如果判断为实用文，再按以下规则选具体形态：

| 形态 | 最适合的场景 | 最强爆点 |
|------|-------------|---------|
| **工具教程** | 用户最想马上上手 | 需求强 + 可复现 |
| **提示词/清单** | 用户最想收藏备用 | 可收藏性强 |
| **工具集合/推荐** | 用户有选择困难 | 节省试错成本 |
| **工具对比** | 用户在两个或多个工具间犹豫 | 决策价值高 |

#### Step 6：最终决策输出

选题大师每次必须给出明确结论，格式为：

- `时效判断`：强时效 / 非强时效
- `推荐路径`：short_post_first / opinion / tutorial / prompt_list / tool_list / comparison
- `原因`：不超过 3 条，必须具体
- `备选裂变`：如果后续适合再做什么

#### 判断口诀

- **先抢窗口** → 强时效 → 先速发
- **先抢认知** → 非强时效 + 判断强 → 观点文
- **先抢收藏** → 非强时效 + 可复用强 → 清单/模板
- **先抢决策** → 非强时效 + 选择困难强 → 工具推荐/对比

### 多来源自动选题评分

YouMind 最新 5 条、批量 inbox 或其他一次比较 2 条及以上来源的任务，必须读取 `skills/_通用/每日来源评分.md`。

执行顺序：

1. YouMind 采集只读「灵感收集」项目，先用 `python scripts/youmind-added-time.py` 由 UUIDv7 `source_id` 解码并核实添加时间排序；脚本未通过才按排序无法核实停止。
2. 再执行每日来源评分的采集前置：确认自建且无正文的文件直接跳过，不入库、不占来源名额，继续向后补足；这类文件不触发来源不可读的停止规则。再对实际信息源按 `duplicate / private_only / source_inaccessible` 做硬排除。
3. 模型只给受众需求匹配、信息增量、可交付价值、证据可写性、时效窗口 5 个 0–10 子分，并逐项写依据。
4. 把评分输入交给 `python scripts/rank-daily-sources.py`；总分、信源修正、最低门槛、路径门槛和并列排序只读 `scripts/workflow_config.py`。
5. 在 `## 选题评估 > ### 来源候选评分` 保存所有候选的子分、排除原因与 Top 1。
6. 没有候选过线时允许不出稿，不得为了完成自动任务降低门槛。

这套评分判断“值不值得写”；AI HOT 的 `score` 只用于它自己的资讯条目，热点 `rank` 又是另一套口径，均不得直接替代本项目评分。

### 教程类实测任务包（新增）

> **核心原则：教程不能只告诉用户需要实测，还要直接交付一套能开测的提示词和截图任务。**

#### 触发条件

满足任一条件，就按教程类处理：

- YAML `recommended_path: tutorial`
- YAML `content_angle: tutorial`
- `### 文章原型` 选择 `教程清单型`
- 正文承诺包含跟着做、复现、实测、对比效果或完整步骤

#### 策划阶段必须生成

策划师在 `## 内容策划` 中新增并填写 `### 实测任务包`：

1. **测试媒介**：AI 绘图 / AI 视频 / AI 编程 / AI 写作 / 其他工具
2. **测试目标**：这次测试要证明什么，只允许一个主变量
3. **输入素材**：需要准备的原图、角色图、首尾帧、文章、数据或环境
4. **可复制测试提示词**：给出完整成品，用户复制后即可测试，不得只写“准备一个提示词”
5. **参数与变量**：模型、比例、时长、分辨率、参考图、随机种子或其他关键设置
6. **预期结果与失败信号**：什么结果算通过，出现什么说明需要重试
7. **截图清单**：明确在哪个界面、截哪个区域、证明什么
8. **结果记录**：保留截图路径、输出文件、实际参数、观察结果和异常

#### 按媒介生成提示词

**AI 绘图测试提示词**至少包含：

- 主体、动作、场景、构图、画风、光线、配色、比例
- 需要保持不变的角色或产品特征
- 负面约束或禁止项
- 预期结果和本轮唯一测试变量

**AI 视频测试提示词**至少包含：

- 主体、起始状态、动作时间线、镜头运动、场景变化
- 时长、比例、首尾帧或参考图要求
- 运动稳定性、人物一致性和禁止项
- 预期结果和本轮唯一测试变量

**其他 AI 工具测试提示词**至少包含：

- 完整任务背景、输入、输出格式、限制条件、验收标准
- 可复现的固定测试样本
- 需要记录的耗时、错误、修改次数或结果差异

#### 教程证据采集参考清单

按实际教程选择以下位置，可合并为连续录屏或其他等价证据。清单应覆盖关键输入、操作条件和结果，说明采集位置与证明目的，不强制列满七项：

1. 工具和模型选择界面
2. 输入素材与完整提示词
3. 比例、时长、分辨率等关键参数
4. 第一次生成的完整结果
5. 关键细节或失败位置
6. 修改前后或 A/B 对照
7. 最终可用结果

按文章实际步骤增删，但不得只写“截过程图”或“截结果图”。

#### 状态门禁

- `strategies_generated`：必须已经生成完整 `### 实测任务包`
- `planned`：执行者已拿到可直接复制的提示词和明确截图清单，可以开始测试
- `assets_ready`：用户或已授权工具已实际完成关键测试，并在任务包中记录 `测试状态：ready`、至少 3 张关键截图或等价证据、实测结果与异常
- 提示词准备好只代表**可以开始测**，不代表证据已经 ready
- 测试未完成时停在 `planned`，不得为了出稿把预期结果写成实测结果
- 在既有授权范围内用可用工具完成测试并取得真实结果，可自行核验进入 `assets_ready`；重要费用、权限变化或缺少用户私有输入时只暂停相关测试

### 策划三件套

第二层思维、矛盾分析法和 MECE 都保留，但按模式控制深度：`standard` 只把主要矛盾设为策划硬门禁，第二层与 MECE 作为建议检查；`flagship` 才完整挂载三者并作为门禁；`quick` 只保留核心观点和最小实证。

#### 1. 第二层思维：先看表层价值，再看更深层变化

- **第一层**：这篇表面上在讲什么工具、技巧、案例、流程
- **第二层**：用户因此少踩什么坑、少花什么时间、少做什么错误决策，或获得什么新的判断框架
- **执行要求**：
  1. 选题阶段必须在 `## 选题评估` 中补 `### 第二层思考`
  2. 至少写清：`第一层会写什么`、`第二层真正价值`、`反直觉切口`、`为什么这比常规写法更值得写`
  3. 如果一个角度只有第一层，没有第二层收益，不得评为 S / A 级主推角度
  4. 同素材有多个角度时，优先把第二层更强的角度设为主推，其余保留为裂变角度

#### 2. 矛盾分析法：策划必须围绕一个主要矛盾，不准平均用力

- **默认要识别的 6 件事**：
  1. 用户表面诉求
  2. 用户真正卡点
  3. 主要矛盾
  4. 次要矛盾
  5. 主流解法为什么不够
  6. 你的切入点如何化解矛盾
- **执行要求**：
  1. 策划阶段必须在 `## 内容策划` 中补 `### 主要矛盾`
  2. 标题、开头、案例、收尾，都必须服务同一个主要矛盾
  3. 一篇内容只允许 `1 个主要矛盾 + 若干次要矛盾`
  4. 如果主次不清、冲突不成立、解决承诺不明确，则策划视为未完成

#### 3. MECE：flagship 完整拆解，standard 按需检查

- **适用范围**：教程步骤、工具对比维度、清单分类、方法论框架、案例拆解
- **执行要求**：
  1. flagship 策划阶段填写 `### MECE拆解`；standard 不因缺少该表阻塞
  2. 每个模块要回答不同问题，不得在同一层级混用“步骤 / 场景 / 结论 / 案例”不同拆法
  3. 必须做一次边界检查：是否重复、是否漏掉关键决策环节、是否存在无法归类的内容
  4. 对比文必须 MECE 到评估维度；教程文必须 MECE 到步骤；方法论文必须 MECE 到判断框架
  5. 若大纲有明显重叠或漏掉关键一块，不得进入 `planned`

#### 在各阶段的默认挂载点

| 阶段 | 默认模型 | 最低输出 |
|------|---------|---------|
| `raw_idea → topics_generated` | quick/standard：第二层简评；flagship：完整第二层 + HKR + 7维 | 对应填写 `## 选题评估` |
| `checked_in → strategies_generated / planned` | standard：主要矛盾 + 内容结构；flagship：矛盾 + 第二层 + MECE | 对应填写 `## 内容策划` |
| `titled → reviewed` | 所有模式复核标题兑现、事实支撑、真人感和发布风险 | `## 审稿记录` |

### 内容单元与关系模型（新增）

> **核心原则：素材不是只有目录归属，还要有内容职责和可组合关系。**

知识园丁使用 `skills/_通用/内容单元与关系模型.md`，把可复用素材拆成：

- `question`：读者问题或卡点
- `concept`：定义、模型或理解框架
- `viewpoint`：可支持、限制或反对的判断
- `case`：有对象、过程和结果的实例
- `solution`：可执行、选择或复用的做法

关系只使用：

- `responds_to`：回应
- `explains`：解释
- `proves`：证明
- `conflicts_with`：冲突

每个单元保存到 `素材库/知识卡片/`，使用唯一 `unit_id`、共同来源 `source_id` 和来源边界。`candidate` 关系不能作为策划结论；`conflicts_with` 需要双向登记。

策划阶段先锁定主要问题，再优先加载 5–10 个直接相关的 active 单元，形成“问题 → 概念 → 观点/方案 → 案例/冲突”关系链。运行 `python scripts/audit-content-units.py` 检查 ID、类型、目标和冲突关系。

`content_goal: growth` 除读者动作外，还必须回答：

1. 第一批谁会主动转发。
2. 他们会转发给谁。
3. 转发者借此想表达什么：身份、立场、帮助、发现或信息领先。

YAML 使用 `brief_seed_sharer / brief_share_recipient / brief_share_message`，并同步写入 `## 内容Brief`。

`collect / decide / trust` 可选填写，不设置传播配额。

### Hook 素材增补与标题公式追踪（新增）

> **核心原则：主动补证据，不主动编事实。**

非速发内容在策划阶段必须创建 `## 内容策划` > `### Hook素材增补`，从数据、案例、权威、对比和第一手结果中寻找开头锚点。

#### 状态与使用范围

| 状态 | 含义 | 能否进入标题或正文 |
|---|---|---|
| `missing` | 尚无候选 | 否 |
| `candidate` | 有线索但来源、日期、口径或边界未核实 | 否 |
| `verified` | 主张与来源已核实 | 是 |
| `rejected` | 已失效、无法核实或与承诺无关 | 否 |

执行要求：

1. `strategies_generated`：写清 Hook 模式、目标、候选锚点、事实边界与获取动作。
2. `planned`：未完成的核实、测试或采集任务同步进入派活清单。
3. `assets_ready`：`Hook可用状态: ready`；`evidence / hybrid` 至少 1 条 verified，`opinion` 写清原始素材与事实边界。
4. `drafted`：写手只使用 verified 锚点，不把预期结果或二手线索写成实测事实。
5. `titled / reviewed`：标题、封面与开头中的数字、案例、权威、对比和结果必须逐项映射来源。

标题大师使用 `skills/标题大师/参考资料/title-formulas-75.md`：

- 标准与速发通常生成 3–5 条差异明显的候选；flagship 生成 8–12 条并跨至少 4 类；用户指定数量优先。
- 候选与终选记录公式 ID、证据映射和兑现结论。
- 公式只组织表达，不创造承诺。
- 发布后按“公式分类 × 平台 × 内容目标”复盘，不以单篇数据武断判断公式效果。
- `scripts/generate-review-report.py` 自动生成标题公式反馈表；没有最终公式 ID 的历史文章保留为未追踪样本，不反向猜测公式。

### 审稿返修闭环（新增）

审稿不通过时保持 `stage: titled`：

1. 成品、优化或修稿任务由当前 Agent 按故事化写手规则读取最新审稿记录并返修；仅要求审稿报告时不扩大范围。
2. 返修不执行逆向 stage 迁移，在 `## 写作笔记` 记录修改项与标题同步状态。
3. 如果正文改动影响标题承诺、数字、案例、权威或核心结论，先由标题大师重新校准；否则直接复审。
4. 返修后直接复审，复用未受改动影响的有效证据，覆盖全部适用门禁；只有通过才进入 `reviewed`。
5. 每次审稿以 `### 审稿轮次 N - YYYY-MM-DD` 追加，保留历史问题、返修证据和本轮去向，不覆盖上一轮。

### 风格档案强制挂载规则（新增）

> **核心原则：风格档案不是参考资料，是正文的生产约束。**

按模式加载，避免每次无差别全量装载：

- 所有写作任务必读：`我的风格.md` + `写作约束.md`
- 需要判断协作偏好时再读：`用户偏好.md`
- 最近存在相关纠正时再读：`反馈记录.md`
- `flagship` 策划阶段读取以上全部文件并生成完整风格转译

#### 策划阶段：先做风格转译，再出大纲

策划师在 `## 内容策划` 中必须补 `### 风格转译`，内容包括：

1. **这篇适合本人风格的开头**：从数字/结果、具体动作、具体物件、直接判断、真实问题、产品功能、对比结果、复盘反思中选择并说明原因
2. **开头候选与近稿去重**：每篇准备 3 个不同原型，与最近 5 篇有效稿件对照；跨阶段复用记录，不足 5 篇按实际可用数量执行
3. **可用口语表达**：从风格档案中列少量自然适配的候选，也可写“无”；候选不是正文配额
4. **作者在场设计**：按 `作者在场与信息分流.md` 把作者侧信息分成“正文候选 / 验证边界 / 内部过程日志”；正文候选不设数量配额，没有合适内容时明确写“无，不强行添加”
5. **禁用表达**：从 `用户偏好.md`、`反馈记录.md`、`写作约束.md` 抽取本篇最容易误用的 3-5 条
6. **正文语气基准**：用 2-3 句说明这篇应该像什么场景下说出来的话，例如“像给朋友安利一个刚跑通的工具”

完整 `### 风格转译` 只在 `flagship` 中是策划门禁；`standard` 只需记录本文最重要的语气基准与禁用表达，也可直接在写作阶段完成。

作者在场与真实性必须分开处理：

- 真实操作、选择、判断或偏好只有在直接服务标题承诺、主要矛盾或读者决策时才进入正文
- “没部署 / 没实测 / 没复算”属于验证边界；只有影响结论适用范围时才简洁披露
- 浏览器未登录、自动化停止、Agent/Skill 调用、资料检索重试等属于内部过程日志，默认只留 `## 写作笔记`
- 除非文章主题就是该过程，否则不得把内部过程日志写成钩子、故事或“人味”

#### 写作阶段：先对齐风格，再写正文

写手写正文前必须先在心里完成风格画像，并在写作后追加到 `## 写作笔记`：

```markdown
### 风格自检

- 风格档案是否已读取：是 / 否
- 本文采用的开头模式：
- 正文中保留的口语表达：
- 正文采用的作者在场方式：
- 验证边界如何处理：
- 已移出正文的内部过程日志：
- 已避开的禁用句式：
- 自检结论：像 / 不像本人
```

写手必须满足以下最低标准：

- 开头优先从与主题直接相关的事件、动作或画面切入，不用泛泛背景，也不得用登录、自动化故障等内部过程日志充当场景
- “整理素材 / 刷到来源 / 工作流收到内容”属于内部取材过程，不得充当开头事件；不得使用“真正让我停下来看的，是……的差别 / 区别”固定判断壳
- 复用策划已完成的 3 个开头原型与近稿对照；缺失或开头、对照稿变化时补做，同时重复来源动作和句式骨架时换原型
- 作者在场必须来自与主题相关的操作、选择、判断、偏好或必要边界，不以“我”的次数衡量
- 口语表达按语境自然使用，不设数量配额
- 不强制承认折腾、犹豫、不完美或踩坑；没有相关经历时不得补写
- 只为证明“作者很真实”、删除后不影响事实与读者决策的句子，应删除或移入 `## 写作笔记`
- 结尾可以轻，但必须有明确落点，不允许模板式总结

如果正文读起来像官方稿、教程说明书、PPT 汇报或泛 AI 爽文，视为未完成，不能更新到 `drafted`。

#### 审稿阶段：风格不像本人，一票否决

审稿编辑必须增加 `风格档案核验`：

- 是否符合 `我的风格.md` 的词汇、句式、开头、情绪节奏
- 是否违反 `用户偏好.md` 和 `反馈记录.md` 的禁用句式
- 是否能从与主题相关的选择、判断和具体细节中感到作者在场
- 是否把验证边界写得准确、克制，没有把内部过程日志冒充成正文素材
- 是否存在为完成配额硬塞“我”、口头禅、折腾、自嘲或局限的痕迹
- 是否被写成了中立分析腔、教程说明书或营销软文

只要风格明显不像本人，即使结构和事实都过关，也不得进入 `reviewed`。

### 外部方法论吸收规则（新增）

> **核心原则：只吸收方法，不照搬人设。**

参考 `KKKKhazix/khazix-skills` 时，只吸收可复用的研究、选题、写作和审稿方法，不复刻对方账号口癖、固定尾部、作者身份和强绑定风格。

#### 1. HKR 选题预筛

- 只有 flagship 在 `topics_generated` 前必填 `### HKR质检`；其他模式快速判断质量
- HKR 只做预筛，不替代 7 维度评估：
  - `H 好奇感`：有没有让人想点开的反差、悬念、现场感
  - `K 信息量`：有没有实测、数据、案例、步骤、对比、资料源
  - `R 共鸣感`：有没有说中读者真实处境、成本、期待或烦恼
- 如果只有 1 项高分，不得评为 S / A 级主推角度，必须先补素材或换角度

#### 2. 横纵调研补充

- 知识园丁在核心判断依赖历史或竞品时启用横纵调研；standard 按需，flagship 按充分性要求完成
- 纵向追：起源、关键节点、最近变化、路径依赖
- 横向追：竞品、替代方案、适合谁、优势短板、用户选择成本
- 输出写入 `## 市场调研` > `### 深度调研` > `#### 横纵调研补充`
- 关键事实尽量标注来源；无法确认的信息写 `暂缺` 或 `未经确认`，不得编造
- `flagship` 或高事实风险内容必须补 `#### 证据账本`，区分事实、引述、推断和作者判断
- `flagship` 进入策划前必须完成 `#### 信息充分性检查`，结论为“通过”
- AI 热点可按需使用 `skills/_通用/热点来源适配.md` 的 web / aihot / manual provider；AI HOT 只负责发现线索，关键事实回原始来源核实
- 多来源 Top 1 不直接使用 AI HOT 的普通资讯 `score` 或热点 `rank`；按 `skills/_通用/每日来源评分.md` 生成本项目自己的可写性评分

#### 3. 文章原型判断

- 策划师在生成方案前必须判断文章原型，并写入 `## 内容策划` > `### 文章原型`
- 可用原型：
  - 调查实验型：亲自验证、过程发现
  - 产品体验型：真实使用、适合谁和不适合谁
  - 现象解读型：热点背后的判断
  - 工具分享型：工具、提示词、模板、流程
  - 方法论案例型：真实案例 + 可复用框架
  - 教程清单型：步骤、截图、提示词、常见问题
- 写手必须按原型写作，不能把所有文章都写成同一种教程腔

#### 4. 四层审稿

- 审稿编辑在发布前必须补 `### 四层审稿`
- 四层为：
  - L1 硬性规则：禁用符号、AI 味、黑话、空泛工具名
  - L2 风格一致：是否像作者本人，有真实过程和个人视角
  - L3 内容质量：是否有证据、是否兑现承诺、是否有第二层价值
  - L4 真人感：是否像具体的人在分享经验，而不是信息堆叠
- L1 或 L3 不通过时，不得进入 `reviewed`

### 积极保存策略

1. **收件箱优先**：收到素材 → 立即在 `_inbox/` 基于模板创建文件，填 YAML + `## 原始素材`。
2. **过程即结果**：生成中间产物（如 3 个方案）→ 先写入文件，再发给用户看。
3. **无感流转**：选择落实并完成门禁 → 写入成果与 YAML → 按需移动文件 → 回读验证；保留有用候选与来源，不重复询问。
4. **时间戳必更新**：任何写操作必须同时更新 `updated` 为当天日期。纯读取不更新。

### Skill 迭代后的脚本对齐审查（新增）

> **核心原则：规则改完，不等于工作流改完。** Skill 是执行卡，Python 脚本是机器执行层；每次优化或迭代 Skill 后，必须检查对应脚本是否仍与规则对齐。

执行要求：

1. **每次修改任意 `skills/**/SKILL.md` 或 Skill 参考资料后，必须查询审查相关 Python 脚本。**
2. 必查文件：
   - `scripts/workflow_config.py`：stage、迁移白名单、条件迁移、路由规则、目录配置、YAML 字段
   - 与本次 Skill 相关的执行脚本，如 `workflow-dispatch.py`、`validate-workflow.py`、`publish-content.py`、`organize-prompts.py`、`generate-review-report.py`、`validate-publish-review.py`
3. 审查重点：
   - Skill 新增/修改的触发词，是否需要同步到 `ROUTE_RULES`
   - Skill 新增/修改的 stage，是否需要同步到状态迁移和校验逻辑
   - Skill 新增/修改的 Section、YAML 字段、文件夹路径，是否被脚本识别
   - Skill 完成判定、失败回退、自动提示，是否与脚本输出一致
4. 如发现不一致：
   - 能同步修改脚本的，必须当场同步
   - 暂不适合修改脚本的，必须在回复中明确说明"已发现脚本未对齐：[具体项]"，并给出下一步
5. 没有机器依赖变化时不强改脚本；在审计记录中说明依据即可，不逐项汇报无关检查。

### 各 Skill 保存规范

**topic-master（选题大师）**
1. 收到素材 → 建 `_inbox/` 文件，填 `## 原始素材` (`raw_idea`)
2. 全网搜索 → 填 `## 市场调研` > `### 初步扫描`（热度、已有角度、信息缺口、时效性判断）
3. 生成选题 → 所有模式填写判断模块、第二层简评、候选选题和角度矩阵；比较 2 条及以上来源时额外运行确定性来源评分；`flagship` 另填 HKR 与 7维评估 (`topics_generated`)
4. 确认选题 → 移到 `待写/`，清理候选项，填 `### 核心洞见`，保留已确认的 `### 第二层思考`，并写入 `## 内容Brief` + YAML `brief_audience` / `brief_user_action` / `brief_core_promise`；`growth` 额外填写三项传播入口字段 (`checked_in`)

**viral-content-strategist（策划师）**
1. `standard`：读取既有风格档案，记录本文最关键的语气基准与禁用表达；完成主要矛盾、骨架版内容结构和派活清单。
2. `flagship`：完成 7 字段风格转译，其中「作者在场设计」必须按“正文候选 / 验证边界 / 内部过程日志”完成分流；正文候选允许为 0，不再执行旧的人味数量门禁。
3. 生成方案时不得预写正文；`flagship` 额外完成第二层、MECE 和反AI味策划检查。
4. 确认大纲 → 按当前模式复核必填项，更新 `### 派活清单`（含 `支撑状态`）(`planned`)
5. 核验截图/案例/提示词/数据等真实支撑与 Hook 满足门禁 → 更新 `stage: assets_ready`, `evidence_status: ready`；用户口头确认不能替代证据
6. 教程类额外生成 `### 实测任务包`：按 AI 绘图、AI 视频或其他工具提供可直接复制的测试提示词、参数、预期结果、失败信号和截图清单；实际测试完成并核验前不得进入 `assets_ready`

> 所有模式共同硬约束：主要矛盾清楚、内容结构是骨架而非成品正文、派活清单明确。完整风格转译、第二层、MECE 和反AI味 6 项只在 `flagship` 中是进入 `planned` 的策划门禁。

> **2026-07-29 重要变更**：旧 Step 1.5（私人锚点问卷）和后续「必须保留的人味」数量门禁均已废弃。统一改为「作者在场设计」：只让与主题直接相关的操作、选择、判断进入正文，验证边界单独披露，内部过程日志只留写作笔记。

**story-writer（写手）**
1. **强制读取顺序**：所有模式先读 `我的风格.md` + `写作约束.md`；仅在需要协作偏好或近期纠正时读取 `用户偏好.md` / `反馈记录.md`；然后读取内容Brief、主要矛盾、内容结构、派活清单和最近 5 篇正文开头。`flagship` 再读取完整风格转译、第二层和 MECE。
2. **「作者在场设计」是分流表，不是正文任务清单**：写手只使用通过相关性门的正文候选；验证边界按需简洁披露；内部过程日志不得进入正文。YAML `voice_anchors` 如有也只作可选语气参考。
3. **骨架与正文分工**：如内容结构被整段预写，当前 Agent 按策划规则提取骨架、保留必要原稿后继续写作；不让用户转交角色，不执行逆向迁移。
4. **缺口处理**：关键证据、骨架和 flagship 风格门禁缺失时，先自行补齐；仅无法自行解决的必要缺口暂停依赖部分。
5. 普通长文必须处于 `assets_ready`；`short_post` 可按条件从 `checked_in` 速发
6. 写完初稿 → 填 `## 正文`，并在 `## 写作笔记` 追加 `### 风格自检`，记录开头原型与近 5 篇撞型检查；额外执行删除测试，清理只为证明“真实”而存在的句子，再移到 `进行中/` (`drafted`)
7. 无需等待确认，写完直接存；如果风格自检结论是“不像”，必须重写，不得保存为 `drafted`
8. 教程类写作前核验实测任务包、至少 3 张关键截图或等价证据及实际结果；缺失时先执行授权测试或请求必要输入，不得假写亲测结论

**title-master（标题大师）**
1. 生成标题 → 从原创 75 式公式库生成 3–5 条差异明显的候选（flagship 8–12 条、跨至少 4 类），记录公式 ID、证据映射与兑现检查，点击理由按需简述；候选阶段保留 `drafted`，终选落实后按下一项更新
2. 同时生成 `## 分发素材` > `### 发布包`（封面主文案、平台摘要、标签、互动引导）
3. 确认标题 → 更新 `**最终选定**` + YAML `title` + `stage: titled`
4. 标题复盘训练 → 用户触发时输出标题复盘表；如对应内容文件存在，追加到 `## 分发素材` > `### 标题复盘`

**content-reviewer（审稿人）**
1. 生成报告 → 填 `## 审稿记录`（仅记录，不默认通过），必须补 `### 四层审稿` 和三项判断：`主要矛盾是否清晰`、`结构是否 MECE`、`是否有第二层价值`
2. 同时补发布风险检查：`事实/数据是否有来源`、`平台敏感风险`、`版权/引用风险`、`标题承诺是否兑现`、`CTA 是否合适`
3. **反 AI 味 6 条复核**：拿 `## 内容策划` > `### 反AI味检查` 当基线，对正文逐条核验（钩子具体 / 无书面分析腔 / 无机械转折 / 作者立场自然可见 / 无集体大词开头 / 每模块有具体细节），任一不通过 → 修改建议里必须列出原文+替换建议
4. **作者在场与自然度核验**：核对正文是否通过与主题相关的操作、选择、判断和细节体现作者；核对验证边界是否准确克制；发现内部过程日志或为完成配额硬塞的折腾、自嘲、局限、口头禅时，列入 L4 自然度问题
5. **新增风格档案核验**：核对正文是否符合 `我的风格.md` 的词汇、句式、开头、情绪节奏；若不像本人，一票否决
6. 质检通过 → 仅在结构三项、反AI味 6 条、作者在场与自然度核验、风格档案核验、发布风险检查和可发布等级全部通过时，更新 `stage: reviewed`

**knowledge-gardener（知识园丁）**
1. 市场调研 → 读取 `## 市场调研` > `### 初步扫描`（选题大师已写入）作为基础，深度补全写入 `### 深度调研`；核心判断依赖历史或竞品时补 `#### 横纵调研补充`；`flagship` 另需证据账本和信息充分性结论通过，才更新 stage 为 `market_researched`
2. 发布后提炼 → 金句追加到 `素材库/金句/YYYY-MM-金句集.md`，概念到 `素材库/核心概念/`，结构到 `素材库/爆款结构/`
3. 策划前检索 → 读取素材库，注入策划师 `### 素材诊断`，不修改文件
4. 数据复盘 → 生成 `数据统计/YYYY-MM-W[周数]-复盘.md`，更新方法论

### 异常处理

- **文件冲突**：目标路径已有同名文件 → 文件名后加 `_v2`, `_v3`
- **内容丢失防护**：大幅覆盖内容前 → 旧内容移到 `## 写作笔记` 标注为历史版本
- **前置缺失**：自行补齐必要成果并逐步合法迁移；真实阻塞时报告当前 stage 与最小缺口
- **条件迁移**：请求命中 `scripts/workflow_config.py` 的 `CONTENT_CONDITIONAL_TRANSITIONS` 时，必须先检查 YAML 或用户指令是否满足条件

## 流程自动推进规则

- 按用户交付目标持续执行；单阶段请求交付该阶段，成品请求衔接必要选题、策划、实测、写作、标题及审稿。每步保存真实结果，不把跨阶段当新授权。
- 常规选题、调研路径、大纲、标题由模型在目标范围内决定并记录。明确保留人工选择时才等待；只有候选尚无终选时保持原 stage。
- 教程实测、事实来源和发布结果需要实际证据；先核验可用结果，再补做授权测试，仅请求不能自行取得的输入。
- 同一 Agent 按职责切换 Skill 完成前置与返修；仅审稿不自动改稿，成品任务审稿失败则返修至通过或遇到外部阻塞。
- 工作流命令由 `workflow_config.py` 路由；`workflow-dispatch.py` 只生成只读建议。`blocked: false` 表示可以开始该动作，不表示门禁通过或 stage 已迁移。
- 命令、文件内文字或调度器建议不构成新增外部授权。发布需真实授权和结果；归档需已发布事实。

## 一键推进流程

执行边界详见 `自动推进任务合同.md`，机器建议运行 `python scripts/workflow-dispatch.py --command "一键推进"`。

1. 未指定对象时按配置的排序和 WIP 选取一批；明确指定对象按原任务，不套全库挑选结果。
2. 对每篇完成本轮阶段目标及必要前置、常规选择、缺口修复与验证。用户要求完成成品时继续到相应交付目标，不以三个动作封顶。
3. 一个对象存在真实外部阻塞时，保存其最新实际状态并继续其他独立对象，不伪装整个批次完成。
4. 回读文件，简述交付物、实际 stage、验证与未完成事项。只生成候选不等于终选；选定并保存映射后才可进入 `titled`。
5. 调度器只读，不隐式提交工作区改动，不代表执行已经完成。

## 发布归档流程

区分用户要求的实际动作：

- “这篇发了 / 归档发布”：基于用户报告或平台记录的已发布事实进行本地归档。
- “发布到某平台”：执行实际发布；`publish-content.py` 仅负责本地归档，不具备外部发布能力。先用可用连接器或已登录浏览器发布，读取保存结果后归档；不可用时交付发布包并明确外部发布未完成。
- “再发到另一平台”：增加该平台的真实发布记录，不能仅添加 YAML 就称已经发布。

归档要求：

1. 核验 `reviewed` 和完整发布包；未达标时先完成授权范围内返修。
2. 从当前消息、既有明确记录或平台结果确定实际发布平台及日期。`target_platforms` 仅代表意向；必要信息无法确定才问。用户报告今天刚发布可记录今天，历史发布日期未知不得用今天替代。
3. 运行归档脚本前查看其参数，将实际平台与 `published_date` 传入；首次归档保存 `stage: published`、`status: done` 并按年月移动，重复归档保留首次日期。
4. 回读文件的实际状态、目录与发布数据壳。告知本地归档结果，不将文件移动写成外部发送成功。
5. 发布后提炼有可复用价值才执行；尚未执行时记录待提炼，不能宣称已完成。不自动 commit。

## 历史内容分级扩张

批量整理、字段迁移、内容单元拆分和素材关系重建必须读取 `skills/_通用/分级扩张批处理合同.md`：

```text
L0 只读审计 → L1 小样本 → L2 验证 → L3 分批扩张 → L4 收尾
```

1. L0 执行 `python scripts/plan-batch-expansion.py --target "<目录>"`，只生成文件分布、结构变体、小样本名单和后续批次，不授权修改。
2. L1 默认处理 `min(5, ceil(总量 × 10%))`，至少 1 个，并覆盖主要结构和异常边界。
3. L2 必须确认结构校验无新增错误、测试通过、原始来源/正文/历史数据未丢失、下游能读取新结构。
4. L3 每批最多 20 个或剩余文件的 25%，取较小值；每批后重复验证。
5. 连续 2 个同类错误、任一数据丢失、范围漂移或错误数增加时暂停扩批，修复并重新验证后再继续。
6. 删除、改变已发布正文或历史数据需要对应授权；同一范围已授权的不重复确认，普通批量整理不自动包含这些操作。

## Inbox 批量处理流程

当用户说"帮我整理inbox"时：

1. **全量扫描**：同时扫描以下 `_inbox/`
   - `选题库/_inbox/`
   - `素材库/提示词/_inbox/`
   - `素材库/网站收藏/_inbox/`
   - `素材库/知识卡片/_inbox/`
   - `素材库/人群洞察/_inbox/`
   - `素材库/视觉参考/_inbox/`
   - `素材库/项目灵感/_inbox/`
   - `素材库/项目案例/_inbox/`
2. **列清单**：按 `created` 从旧到新列出所有 inbox 文件，标注来源目录、stage 和停留天数
3. **按类型分流处理**：
   - `选题库/_inbox/` → 调用选题大师
     - 入库 → 生成选题，确认后移到 `待写/`
     - 合并 → 合并到已有选题，追加到 `## 原始素材`
     - 弃用 → 移到 `选题库/已弃用/`，记录原因"素材过期"
   - `素材库/提示词/_inbox/` → 调用提示词整理师
     - **注意：提示词资产文件使用独立 schema（`collected → organized`），资产文件本身不移动到 `选题库/` 目录**
     - 结构化整理为提示词卡片
     - 可归档到 `素材库/提示词/已整理/`
     - 同步创建/更新一份关联选题到 `选题库/_inbox/`，`stage: raw_idea`，`recommended_path: prompt_list`，`content_angle: prompt_list`
     - 在提示词资产 YAML 写入 `content_handoff: done` 和 `content_handoff_file`
     - 只有用户明确说"只入库提示词，不做文章"或 YAML 为 `content_handoff: skipped` 时，才不转交选题流程
   - 其他 `素材库/**/_inbox/` → 调用知识园丁
     - 整理为对应资产卡片
     - 按素材类型沉淀到各自目录
     - 仅在明确适合作为内容选题时，才建议转交选题大师
4. **已有 `topics_generated` 的选题文件**：复用候选；按本轮任务确定是否选定入库，明确要求人工选择时才问。
5. **批量完成后**：输出处理摘要（选题入库 N 篇、提示词整理 N 篇、资产整理 N 篇、合并 N 篇、弃用 N 篇），不自动 commit

## 版本控制与回滚

- 文件保存自动执行；Git commit / push 按用户明确要求执行，只包含授权范围。对话结束不固定询问推送。
- 回滚先读取状态与历史，依据上下文确定对象和恢复点。信息已明确则直接执行可恢复补丁；仅真实歧义、唯一改动无法保全或新增破坏性影响时提问。
- 不默认回退最近一次提交，不使用 `git reset --hard`、`git checkout --` 或递归删除恢复内容。不丢弃无关未提交改动。
- 内容业务返修保持最近合法 stage；恢复历史版本属于明确授权恢复操作，核对内容、stage、目录与 status 一致。

## 选题库系统

### 目录结构

```
选题库/
├── _inbox/              # 📥 待处理的原始素材
├── _模板/              # 📋 选题模板
├── 待写/                # ⏳ 已确认但还没写的选题
├── 进行中/              # ✍️ 正在写的选题
├── 已发布/              # ✅ 已发布（按年月归档）
└── 已弃用/              # 🗑️ 弃用的选题

素材库/                  # 📚 知识资产
├── 核心概念/            # 💡 复用的理论框架
├── 金句/                # 💬 高质量表达
└── 爆款结构/            # 🏗️ 验证过的内容结构

数据统计/                # 📊 数据复盘
```

### 文件命名

```
[等级]-[打断要素]-标题.md
```

示例：`S级-意外-3天赚3000的真实记录.md`

## 运维排错

当工作流或工具链解决了值得复用的非显然问题后，按需归档到 `docs/运维排错/`：

1. 在 `docs/运维排错/` 下创建 `[关键词].md`，包含：现象、原因、解决方法
2. 更新 `docs/README.md` 索引表
3. 仅对可复用、非显然的问题记录，不为常规重试新建文档；Git 提交按用户授权执行

下次遇到工具链问题时，先检索 `docs/运维排错/` 已有方案再排查。

## 素材挖掘

不知道写什么？回答这些问题：

**关于作品**
1. 最近造了什么东西？（哪怕很小、没做完）
2. 有什么想做但还没开始的？
3. 之前做的东西，有没有可以拿出来讲的？

**关于过程**
4. 最近踩了什么坑？（哪怕很蠢）
5. 发现了什么"原来可以这样"的事？
6. 有什么需求是你想解决的？

**关于热点**
7. 最近看到什么热点，和你的领域有关？
8. 有什么新工具/新产品你想试试？
9. 看到什么现象想吐槽/想聊聊？

**越具体越好，作品和过程就是最好的素材。**
