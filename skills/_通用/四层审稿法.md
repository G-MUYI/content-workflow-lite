# 四层审稿法

> 用途：发布前把稿件从硬伤、风格、内容、真人感四层过一遍。它补充现有审稿标准，不替代 `写作约束.md` 和 `审稿编辑/参考资料/CHECKLIST.md`。

## L1 硬性规则

目标：先扫掉一眼暴露问题的地方。

检查：
- 禁用符号是否出现
- AI 高频句式是否出现
- 互联网黑话是否出现
- 标题和正文是否有机械转折
- 是否有空泛工具名，没有说具体产品或模型

不通过：保留 `stage: titled`，必须先改。

## L2 风格一致

目标：判断像不像作者本人，而不是像说明书。

检查：
- 开头是否从具体场景、故事、问题、发现切入
- 是否有个人视角和真实过程
- 句子节奏是否有长短变化
- 是否通过与主题相关的选择、判断或具体细节体现作者
- 是否准确处理验证边界，且没有混入浏览器、登录、自动化等内部过程日志
- 是否存在为显得真实而硬塞局限、踩坑、折腾或口头禅
- 语气是否符合 `我的风格.md`

不通过：给出建议改法，视问题严重程度决定是否阻断发布。

## L3 内容质量

目标：判断文章是否真的有价值。

检查：
- 每个核心观点是否有证据、案例、截图、数据或亲历支撑
- 是否兑现 `brief_core_promise`
- 是否围绕一个主要矛盾推进
- 结构是否 MECE
- 是否讲出了第二层价值
- 对教程、对比、清单、方法论等类型，是否交付了对应内容

不通过：保留 `stage: titled`，回到策划或写作修。

## L4 真人感终审

目标：通读后判断读者是否能感到这是一个具体的人在分享经验。

检查：
- 有没有只在输出信息，没有真实观察
- 有没有把作者包装得过于完美
- 有没有为了显得专业而牺牲人话
- 有没有哪一段让人注意力断掉
- 结尾动作是否自然，不像营销口播

不通过：标记最需要重写的 1-3 段。

## 审稿记录格式

写入 `## 审稿记录`：

```markdown
### 四层审稿

| 层级 | 结论 | 问题数 | 需要处理 |
|------|------|--------|----------|
| L1 硬性规则 | 通过/不通过 |  |  |
| L2 风格一致 | 通过/不通过 |  |  |
| L3 内容质量 | 通过/不通过 |  |  |
| L4 真人感 | 通过/不通过 |  |  |

**阻断项**：
- 

**优先修改**：
1. 
2. 
3. 
```

只有 L1、L3 全部通过，L2、L4 无明显阻断时，才允许进入 `reviewed`。
