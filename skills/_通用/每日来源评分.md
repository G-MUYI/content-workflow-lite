# 每日多来源选题评分

> 适用于 YouMind 最新 5 条、批量 inbox 或其他多来源候选比较。机器值以 `scripts/workflow_config.py` 为准，计算由 `scripts/rank-daily-sources.py` 执行。

## 为什么这样设计

AIHOT 公开的资讯筛选方法有 4 个可复用原则：先做相关性预筛；模型只给细分分，不直接决定最终精选；代码按固定权重和信源等级算总分；同事件聚类去重，并用历史样本回测规则。

AIHOT 没有公开新闻评分的完整 5 个维度、权重和分类阈值，所以本项目只参考架构，不声称复制其公式。AIHOT 的普通资讯 `score` 也不是热点榜 `rank`，两者不能混用。

参考：

- [AIHOT 作者公开的评分流程](https://watermelonwater.tech/insights/3%E5%B9%B4%E8%87%AA%E5%AA%92%E4%BD%93%E7%BB%8F%E9%AA%8Cai%E7%83%AD%E7%82%B9%E5%85%8D%E8%B4%B9%E5%BC%80%E6%94%BE/)

## 采集范围与添加时间核实

YouMind 每日采集的范围、数量和时区以 `scripts/workflow_config.py` 的 `YOUMIND_SOURCE_BOARD`、`YOUMIND_DAILY_SOURCE_LIMIT`、`YOUMIND_ADDED_TIME_UTC_OFFSET_HOURS` 为准：

- 范围固定为「灵感收集」项目的文件列表，不扩大到全账户或全局“最近”页。全局“最近”页按“更新于”排序，不能作为采集入口。
- YouMind 界面不显示添加时间。添加时间统一由 UUIDv7 `source_id` 的前 48 位毫秒时间戳解码，这是认可的核实方法，不属于推算或替代。
- 解码由脚本执行，不在模型侧手算。项目列表的显示顺序不一定是添加顺序，所以要把列表中全部可见条目的 `source_id`（取自文件链接的 `file-id`，可附 `title`、`published_at`）写成 JSON，运行：

  ```bash
  python scripts/youmind-added-time.py --input sources.json --format markdown
  ```

  脚本按添加时间从新到旧输出顺序。退出码 0 表示排序核实通过；1 表示有 ID 不是 UUIDv7、解码时间晚于当前时间，或早于原帖发布时间，此时按“添加时间排序无法核实”停止。
- 按脚本输出顺序从新到旧读取正文，跳过自建空文件，补足 5 个信息源。`published_at` 只在读取正文后补充，用于复核。
- 采集记录注明“添加时间由 source_id 解码”。不能用更新时间、原帖发布日期，或未经脚本核实的列表位置代替添加时间。
- 同一阻塞连续出现 2 次时，在报告和会话记忆中标为“规则缺口，需要修改工作流”，不再只请求用户提供入口后原样重跑。

## 采集前置：自建空文件不算信息源

按添加时间从新到旧采集时，先识别文件类型，再确定最新 5 个信息源：

- 已确认由用户自行创建或让 YouMind 生成、且没有正文内容的文件，直接跳过。包括空白文件、仅有标题的占位文件，以及明确显示生成失败且无正文的生成文件。
- 这类文件不占 5 个信息源名额、不评分、不入选题库或素材库，不标为 `source_inaccessible`，也不因它中断任务或要求用户先修复。继续向后读取，直到补足 5 个信息源或遍历完可访问列表。
- 跳过项只在采集记录中单列标题、可取得的 ID 和判断依据，不传入评分脚本的 `candidates`。
- 一时空白、尚在加载、读取超时或没有外链，均不足以认定为自建空文件。外部收藏来源不可读仍适用 `source_inaccessible` 和任务的停止规则；自建且有正文的文件仍按以下硬排除规则判断，不因自建身份全部跳过。
- 遍历后不足 5 个时使用实际数量并报告，不捏造来源；没有信息源时保存采集记录并结束，不运行评分脚本。添加时间排序按上一节用 `scripts/youmind-added-time.py` 核实。

## 第一步：先排除

以下任一情况命中，候选保留记录但不得成为 Top 1：

- `duplicate`：同 `source_id + content_angle` 已处理。
- `private_only`：包含不适合公开写作的私人经营信息、客户信息或内部材料。
- `source_inaccessible`：来源正文不可读，关键事实无法取得。

这一步不打分。空白证据也不补 0 分冒充完成。

## 第二步：模型只打 5 个子分

每项 0–10 分，必须给出一句可核对理由。

| 评分项 | 权重 | 10 分是什么样 | 硬门槛 |
|---|---:|---|---:|
| 受众需求匹配 | 25 | 明确命中 AI 内容创作者当前会点开、收藏或采取行动的问题，也符合本人的创作者定位 | 6 |
| 信息增量 | 20 | 有新事实、新方法、新角度或强反差，能明显超过信息搬运 | 无通用门槛 |
| 可交付价值 | 20 | 能交付步骤、模板、提示词、选择标准、判断框架或可复用案例，第二层价值清楚 | 6 |
| 证据可写性 | 25 | 原始链接、官方资料、仓库、截图、数据或可核实案例足够，能支撑标题和正文 | 6 |
| 时效窗口 | 10 | 72 小时内价值明显更高，晚 3–7 天会显著衰减 | 无通用门槛 |

模型不能输出总分，也不能自行改权重。

## 第三步：代码算总分

```text
基础分 = 需求÷10×25 + 增量÷10×20 + 交付÷10×20 + 证据÷10×25 + 时效÷10×10
总分 = 基础分 + 信源修正
```

子分按 0–10 换算到对应权重。信源修正：

| source_tier | 定义 | 修正 |
|---|---|---:|
| `primary` | 官方发布、原始论文、原始仓库、本人实测或一手数据 | +5 |
| `original` | 原作者完整案例、实践复盘、可追溯原帖 | +3 |
| `reliable_secondary` | 可靠媒体或有出处的二手解读 | 0 |
| `aggregation` | 聚合转载、摘要搬运 | -3 |
| `unknown` | 来源身份或出处不清 | -5 |

总分达到 70 才进入 Top 1 候选。并列时依次比较证据可写性、可交付价值、信息增量，最后按稳定 ID 排序，避免同分时随机换第一名。

## 第四步：按文章路径加门槛

- `short_post_first / short_post`：时效 ≥ 7，证据 ≥ 6。
- `tutorial / prompt_list / tool_list / comparison`：交付 ≥ 7，证据 ≥ 7。
- `opinion / methodology / case`：需求 ≥ 7，增量 ≥ 7。

没有候选全部过门槛时，当天允许不出稿。不得为了完成自动任务降低分数、切换角度或把预期证据写成已验证证据。

## 第五步：保存可审计结果

多来源比较时，在 `## 选题评估 > ### 来源候选评分` 保存：

1. 实际候选来源（最多 5 个）的子分、信源等级、修正、总分和排除原因；自建空文件另列采集跳过清单，不进入评分表。
2. Top 1 的选择理由。
3. 未选来源是重复、证据不足、定位不符，还是分数不够。
4. 评分输入的事实边界。AIHOT 只可作为热点发现线索，关键事实仍回原始来源核实。

脚本用法：

```bash
python scripts/rank-daily-sources.py --input candidates.json --format markdown
```
