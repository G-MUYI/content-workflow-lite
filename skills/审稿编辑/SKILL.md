# 审稿编辑 (Content Reviewer)

> 规则边界：本文是执行卡。状态机、迁移白名单、完成判定以 `../../AGENTS.md` 与 `../../scripts/workflow_config.py` 为准。

> **核心策略：积极保存 (Eager Save)**
> 就像体检报告一样，质检结果必须存档。

---

> 协作边界：自主选择、澄清、批准和完成统一按 `../../AGENTS.md` 的“自主执行、澄清与完成”；下文步骤不构成逐步审批，职责切换由当前 Agent 完成。

## ⚡ 自动保存流转逻辑

**触发条件**：
1.  用户指定一个 `进行中/` 的文件（状态 `stage: titled`）。
2.  或者用户刚定好标题，直接继续。

### 流程步骤

1.  **Step 1: 读取上游产出**
    *   读取 `## 正文` 获取完整文章。
    *   读取 `## 标题备选` 获取最终标题。
    *   读取 `## 分发素材` 获取发布包（封面主文案、平台摘要、标签、互动引导）。
    *   读取 `## 内容Brief` 获取目标读者、读者动作和核心承诺。
    *   读取 `## 选题评估` 获取目标人群和核心洞见。
    *   读取 `## 内容策划` > `### 主要矛盾` + `### 第二层思考` + `### MECE拆解`，作为结构质检基准。
    *   读取 `## 内容策划` > `### Hook素材增补`，作为标题、封面和开头的证据映射基线。
    *   **模式边界**：quick 从核心观点、最小实证和风格自检取基线；standard 不要求补齐旗舰策划表，结构检查针对实际正文。
    *   **作者在场基线**：读取 `## 内容策划` > `### 风格转译`（重点是「作者在场设计」字段）+ `### 反AI味检查` 6 条勾选状态 + YAML `voice_anchors`（如有，老文件兼容）
    *   **强制读取风格档案**：读取 [`../_通用/用户偏好.md`](../_通用/用户偏好.md) + [`../_通用/风格档案/我的风格.md`](../_通用/风格档案/我的风格.md) + [`../_通用/风格档案/反馈记录.md`](../_通用/风格档案/反馈记录.md) + [`../_通用/写作约束.md`](../_通用/写作约束.md)
    *   **强制读取信息分流规则**：读取 [`../_通用/作者在场与信息分流.md`](../_通用/作者在场与信息分流.md)

2.  **Step 2: 扫描与诊断**
    *   检查硬伤（禁用词）、人设、可读性。
    *   **执行四层审稿法**：读取 [`../_通用/四层审稿法.md`](../_通用/四层审稿法.md)，按 L1 硬性规则 / L2 风格一致 / L3 内容质量 / L4 真人感 逐层检查。
        -   L1 和 L3 任一不通过，不得进入 `reviewed`
        -   L2 和 L4 如果出现明显人设偏差或读者心流断点，需要列为优先修改
        -   四层审稿统一汇总硬伤、风格、结构和发布风险；相同问题只检查一次，记录可互相引用，保留校验器要求的区块
    *   **新增三项结构洞察检查**：
        -   主要矛盾是否清晰：全文是否围绕同一个核心冲突推进
        -   结构是否 MECE：同层是否重复、是否漏掉关键一块、是否混用不同拆法
        -   是否有第二层价值：文章是否超出"会用工具/知道信息"这一层
    *   **新增反 AI 味 6 条复核（必须）**：拿 `## 内容策划` > `### 反AI味检查` 当基线，对正文逐条核验：
        -   1. 钩子是否从与主题直接相关的场景/数字/动作开始（不是"很多人都"/"我们常常"/"你是否"，也不是登录或自动化故障等内部过程）
            -   开头不得出现“整理素材时刷到 / 看到”或“真正让我停下来看的，是……的差别 / 区别”
            -   对照最近 5 篇 `drafted` 及以上正文，不能同时重复来源动作和句式骨架；只换名词仍算撞型
        -   2. 是否无书面分析腔（正文里没有"本文解决承诺"/"次要矛盾"/"主流解法"，没有用"层/维度/路径/切口/链路"作主语）
        -   3. 是否无机械转折（"不是A，而是B"/"看似A，实则B"/"与其A，不如B"）
        -   4. 作者立场是否通过相关选择、判断或细节自然可见，没有靠配额制造人味
        -   5. 是否避免集体大词开头（"我们都"/"很多人会"/"大家其实"）
        -   6. 主体每个模块是否至少 1 个具体细节锚点（时间/数字/动作/对话/物件）
        -   任一不通过 → 修改建议里**必须列出原文 + 替换建议**（不能只指认问题）
    *   **作者在场与自然度核验（必须）**：
        -   核对正文是否通过与主题相关的操作、选择、判断和具体细节体现作者
        -   对照「作者在场设计」检查三类信息是否放对位置：正文候选按需使用、验证边界准确克制、内部过程日志未进入正文
        -   不要求逐条落地正文候选，也不要求固定数量的“我”、口头禅、折腾或局限
        -   如果正文硬塞 YAML `voice_anchors`、折腾、自嘲、局限或内部过程日志，列入 L4 自然度问题
        -   如果正文比策划参考更书面、更中立、更"分析腔"，同样列入 L4 自然度问题
    *   **新增风格档案核验（必须）**：
        -   核对正文是否符合 `我的风格.md` 的开头模式、短句节奏、口语词、情绪起伏、真实感和收尾方式
        -   核对正文是否落实 `### 风格转译` 中的开头模式、口语表达、作者在场设计、禁用表达和语气基准
        -   **调性档位核验**：核对策划师选定的调性档位（A 兴奋 / B 平实 / C 速评列表）是否落实到正文，没有跑偏成"信息中介 / 平静旁白 / 中立分析"等伪人格
        -   **人格姿态核验**：对照 `我的风格.md` 第七节 7.3 的核心姿态（谦逊、不端着、真诚跟随、有情绪、边界诚实）和禁用人格设定（信息中介 / 旁白者 / 论文派 / 教程主理 / 客观点评者），任一禁用人格触发即一票否决
        -   **引文来源核验**：声称是本人原话或档案引文时核验来源；普通自然口语不要求出自档案，不能把风格基线变成封闭词库
        -   作者的选择、判断或筛选标准应自然可见；不按“我”、口语表达或负面经历的数量评分
        -   核对 `### 风格自检` 已记录开头原型和近 5 篇撞型检查；缺失或结论不通过时不得进入 `reviewed`
        -   如果正文像官方稿、教程说明书、PPT 汇报、营销软文或泛 AI 爽文 → 视为风格失败，一票否决
    *   **新增发布风险检查**：
        -   事实/数据是否有来源：截图、链接、亲历过程或可验证出处是否足够
        -   Hook 证据是否可用：标题、封面和开头里的数字、案例、权威、对比和结果是否逐项映射到 `verified` 锚点；`candidate / missing` 被写成事实时一票否决
        -   平台敏感风险：是否有夸大收益、贩卖焦虑、平台敏感表达
        -   版权/引用风险：是否使用了需要授权的长引用、图片或第三方素材
        -   标题承诺是否兑现：标题/封面承诺和正文交付是否一致
        -   CTA 是否合适：结尾动作是否符合内容目标和平台语气
        -   传播入口是否成立：仅 `content_goal: growth` 必查。第一批转发者、接收者和表达动机是否具体；正文是否真的交付了可转发载体
    *   生成一份审稿报告表格。

3.  **Step 3: 存档报告 (立即执行)**
    *   **追加到 `## 审稿记录` 区块**：每次使用 `### 审稿轮次 N - YYYY-MM-DD` 新建一轮，不覆盖历史审稿结论。
    *   填写日期、等级、硬伤数。
    *   填写 `主要矛盾是否清晰`、`结构是否 MECE`、`是否有第二层价值`。
    *   填写 `### 四层审稿` 表格：L1 硬性规则 / L2 风格一致 / L3 内容质量 / L4 真人感。
    *   **填写 `### 反AI味复核`**（新增表格，6 条逐项标注通过/不通过 + 不通过项的原文与替换建议）。
    *   **填写 `### 作者在场与自然度核验`**（标注作者信息相关性、验证边界、内部过程日志和硬塞痕迹）。
    *   **填写 `### 风格档案核验`**（新增，标注是否像本人，若不像必须给出替换方向）。
    *   填写 `事实/数据是否有来源`、`平台敏感风险`、`版权/引用风险`、`标题承诺是否兑现`、`CTA 是否合适`。
    *   `content_goal: growth` 额外填写 `传播入口是否成立`。
    *   写入修改建议。
    *   在本轮末尾记录 `返修入口：修稿` 与 `下一步：标题 / 复审 / 发布`，让恢复会话时能直接判断去向。
    *   **更新 YAML**：
        *   `agent: content-reviewer`
        *   `updated: [今天日期]`
    *   **状态规则**：
        *   仅当质检结果达到可发布标准时，才更新 `stage: reviewed`
        *   如果存在硬伤、发布风险未处理，或评级未达可发布标准，则保留 `stage: titled`
        *   如果 `主要矛盾不清晰` / `结构不 MECE` / `没有第二层价值` 任一项不通过，也保留 `stage: titled`
        *   **新增**：如果反 AI 味 6 条任一不通过，作者在场与自然度核验失败，或风格档案核验失败（不像本人），也保留 `stage: titled`
    *   *告诉用户*："审稿完成，发现 [N] 处问题。报告已保存到文件。"

4.  **Step 4: 归档引导**
    *   如果评级为 A/S 且硬伤数为 0，三项结构洞察检查全部通过，**反 AI 味 6 条全部通过**，**作者在场与自然度核验通过**，**风格档案核验通过**，且发布风险检查无阻断：
    *   更新 YAML：`stage: reviewed`
    *   "质量达标，人味也保住了。您可以发布了！发布后请说 '这篇发了' 以便归档。"
    *   如果未通过：
    *   仅审稿请求交付问题及替换建议；成品、优化或修稿任务由当前 Agent 按写手规则直接返修，优先处理事实证据、硬伤与风格问题。
    *   返修影响标题或证据映射时先校准，然后直接复审；检查覆盖全部适用门禁，复用未受改动影响的有效证据。

## 检查清单

- 硬伤 (0容忍)
- 人设 (做自己)
- 可读性 (说人话)
- **反 AI 味 6 条**（与策划师 `### 反AI味检查` 同基线）
- **作者在场与自然度核验**（作者信息是否相关、边界是否克制、是否混入内部日志或硬塞人味）
- **风格档案核验**（正文是否像本人，而不只是没有 AI 味）
